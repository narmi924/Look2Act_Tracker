# 摘  要

视线追踪技术能够估计用户的注视方向或屏幕注视位置，在人机交互、辅助输入和无接触控制等场景中具有应用价值。针对专用眼动仪成本高、部署复杂，而普通 RGB 摄像头视线追踪易受光照、头姿、设备和个体差异影响的问题，本文设计并实现了一套基于普通 Windows 计算机和 RGB 摄像头的实时视线追踪与注视交互系统 Look2Act。系统构建了从数据采集、眼区裁剪、模型训练、三维视线估计、屏幕几何映射、用户校准、时序平滑到注视交互的完整软件链路，并实现 Classic 与 Deep 两种运行模式。其中，Classic 模式基于传统图像处理提取眼部特征，Deep 模式基于 GazeNetV2 模型回归三维视线方向。本文自建了包含 31 名用户、16 台设备和 7395 条有效样本的数据集，完成了模型训练、ONNX 导出和 Windows 本地软件部署。实验结果表明，GazeNetV2 在固定测试集上取得 2.8206° 的平均角度误差，在 31 名用户留一交叉验证中取得 2.4788° 的平均角度误差和 321.3820 px 的平均屏幕像素误差。校准实验和系统测试表明，用户校准、几何映射和平滑处理对普通摄像头视线交互的可用性具有重要影响。最终系统能够完成摄像头预览、25 点校准、实时追踪、全屏验证和注视交互演示，适用于注视点可视化、大目标选择和低成本视线交互原型验证。

关键词：视线追踪；普通 RGB 摄像头；深度学习；用户校准；注视交互

# ABSTRACT

Gaze tracking estimates a user’s gaze direction or screen point of gaze and has potential applications in human-computer interaction, assistive input, and touch-free control. Dedicated eye trackers can provide high accuracy, but they are usually expensive and difficult to deploy. In contrast, gaze tracking with a standard RGB webcam is low-cost but sensitive to illumination, head pose, device configuration, and individual differences. To address these issues, this thesis designs and implements Look2Act, a real-time gaze tracking and gaze interaction system for ordinary Windows computers and RGB webcams. The system builds a complete software pipeline from data collection, eye-region extraction, model training, 3D gaze estimation, screen geometry mapping, user calibration, temporal smoothing, to gaze-based interaction. Two running modes are implemented: the Classic mode extracts eye features using traditional image processing, while the Deep mode estimates 3D gaze direction using the proposed GazeNetV2 model. A self-collected dataset containing 31 users, 16 devices, and 7,395 valid samples is constructed for training and evaluation. The trained model is exported to ONNX and deployed in a local Windows application. Experimental results show that GazeNetV2 achieves a mean angular error of 2.8206° on the fixed test set, and obtains a mean angular error of 2.4788° and a mean screen-space error of 321.3820 px in 31-user leave-one-user-out evaluation. Calibration experiments and system tests indicate that user calibration, geometric mapping, and temporal smoothing are important for the usability of webcam-based gaze interaction. The final system supports camera preview, 25-point calibration, real-time tracking, fullscreen verification, and gaze interaction demonstration, making it suitable for gaze visualization, large-target selection, and low-cost gaze interaction prototyping.

Keywords: gaze tracking; RGB webcam; deep learning; user calibration; gaze interaction

# 第一章 绪论

## 1.1 研究背景与意义

视线追踪是指通过采集和分析人眼、面部或头部运动状态，估计用户注视方向或注视点位置的技术。该技术能够反映用户视觉注意力，在人机交互、辅助输入、行为分析、智能驾驶、虚拟现实和认知研究等领域具有重要应用价值。随着计算机视觉和深度学习技术的发展，视线追踪正在从依赖专用硬件的实验室测量技术，逐渐向普通计算设备上的低成本交互技术发展。

传统高精度眼动追踪设备通常依赖红外摄像头、专用光源和角膜反射点检测方法，在受控环境下能够取得较高测量精度。然而，此类设备成本较高，部署条件复杂，对使用距离、光照环境和硬件安装方式具有较强依赖，难以直接普及到普通桌面计算场景。相比之下，普通笔记本电脑和台式机外接摄像头已经广泛存在。如果能够仅依靠普通 RGB 摄像头实现基本可用的视线追踪，将有助于降低眼动交互技术的使用门槛，并为无接触控制、辅助输入和桌面交互提供新的实现方式。

基于普通 RGB 摄像头的视线追踪系统具有明显工程价值，但实现难度也更高。普通摄像头缺少主动光源和红外反射信息，眼区图像分辨率低，容易受到自然光照、眼镜反光、摄像头角度、头部姿态和个体差异影响。即使深度学习模型能够从眼部图像中估计视线方向，系统仍需要解决三维视线方向到屏幕坐标的映射、用户校准、时序平滑和实时交互稳定性等问题。因此，实际可用的普通摄像头视线追踪系统不能只关注模型离线精度，还必须从数据、模型、几何、校准、部署和交互等多个层面进行整体设计。

本文围绕“实时视线追踪技术研究与实现”开展研究，设计并实现了一套基于普通 RGB 摄像头的桌面端实时视线追踪与注视交互系统 Look2Act。系统面向普通 Windows 计算机，完成摄像头输入、人脸与眼区检测、传统视觉特征提取、深度学习三维视线估计、屏幕几何映射、用户校准、平滑处理、全屏验证和注视交互演示等功能。本文的研究意义主要体现在两个方面：一方面，从算法角度探索轻量化深度视线估计模型与屏幕几何映射结合的可行性；另一方面，从工程角度完成可运行的软件系统，验证普通摄像头条件下实现实时注视交互的可能性。

## 1.2 国内外研究现状

### 1.2.1 传统视线追踪与特征方法

早期视线追踪方法主要依赖几何模型和图像特征。专用眼动仪常使用瞳孔中心和角膜反射点之间的相对关系估计视线方向，具有较强物理解释性和较高精度。该类方法通常需要红外光源和精确标定，在实验环境和专业测量场景中应用广泛。国内外关于眼动跟踪技术的综述研究表明，瞳孔检测、角膜反射、眼球建模、头部姿态补偿和标定方法一直是视线追踪领域的重要研究方向[1]。

在普通 RGB 摄像头条件下，由于难以稳定获得角膜反射点，研究者通常采用眼区图像特征进行估计，例如瞳孔中心、虹膜边界、眼角位置、眼睑轮廓和暗色区域质心等。基于特征的方法实现相对简单，计算量小，适合实时系统原型，但其效果容易受光照、眼镜反光、瞳孔可见性和个体差异影响。相关综述指出，特征方法在可解释性和轻量化方面具有优势，但在非受控环境中的鲁棒性仍然有限[2]。

本文系统中的 Classic 模式即属于传统计算机视觉路线。该模式通过眼区灰度化、阈值分割、形态学处理和质心计算提取眼部特征，并通过用户校准映射到屏幕坐标。该路线用于验证传统视觉方法在普通摄像头交互场景中的工程可行性，并与深度学习路线形成方法对照。

### 1.2.2 基于外观的深度学习视线估计

随着卷积神经网络的发展，基于外观的视线估计方法逐渐成为普通摄像头视线估计的重要方向。与传统特征方法不同，外观方法不显式检测瞳孔或角膜反射点，而是直接从眼部图像、脸部图像或全脸图像中学习视线表示。MPIIGaze 等真实环境数据集推动了 in-the-wild 条件下的外观式视线估计研究；UnityEyes 等合成数据方法尝试通过大量可控眼部图像缓解真实数据采集成本问题；全脸外观建模、RT-GENE 和 Gaze360 等工作进一步扩展了自然环境、全脸上下文和大头姿变化条件下的视线估计能力[3-8]。

基于外观的深度学习方法具有较强表达能力，能够从复杂眼部纹理和面部上下文中学习视线相关特征。但该类方法也存在明显挑战。首先，深度模型对训练数据分布敏感，跨用户、跨设备、跨光照条件下容易出现性能下降。其次，模型输出的角度误差并不等同于屏幕交互误差，三维视线方向还需要通过屏幕几何映射和用户校准才能转化为实际注视点。再次，较复杂的模型虽然可能提高离线精度，但会增加实时部署难度，不一定适合普通 CPU 环境下的桌面交互系统。

本文的 Deep 模式采用轻量化 GazeNetV2 模型，以左右眼图像和头姿输入为基础回归三维视线方向单位向量。与直接输出二维屏幕坐标相比，三维方向输出具有更明确的几何含义，便于后续结合屏幕平面求交和校准映射完成注视点估计。

### 1.2.3 校准、个性化与应用评价

视线追踪系统在实际使用中通常需要校准。即使模型在测试集上具有较低角度误差，不同用户眼部结构、摄像头位置、屏幕尺寸和使用姿态仍会造成系统性偏差。校准方法可以通过少量目标点建立原始输出和屏幕目标点之间的映射关系，从而修正用户和设备差异。CalibMe 等研究关注快速、无监督或低负担校准方法；少样本个性化方法则尝试利用少量用户数据提升特定用户上的视线估计精度[9,10]。

除了模型精度和校准误差，系统级评价同样重要。视线交互应用需要关注屏幕像素误差、帧率、延迟、注视点抖动、目标选择成功率和误触发次数等指标。已有研究指出，基于外观的视线估计方法在实际应用中的表现不能仅由角度误差衡量，系统设计、目标尺寸、校准策略和交互任务都会影响最终可用性[11]。

本文将校准作为系统中的关键模块，最终系统采用 5×5 共 25 点校准流程，并在实验中比较不同校准点数和映射方式的影响。同时，本文不只报告模型角度误差，还从屏幕像素误差、跨用户泛化、校准效果、实时运行和交互功能等方面综合评价 Look2Act 系统。

### 1.2.4 人脸关键点、实时工具链与注视交互系统

普通摄像头视线追踪系统需要稳定的人脸关键点检测和眼区裁剪作为前置条件。近年来，实时人脸关键点检测、人脸网格和面部行为分析工具的发展，为普通摄像头下的眼区定位、头姿估计和实时交互提供了基础。MediaPipe Face Mesh、OpenFace 等工具和方法能够提供人脸关键点、头姿和眼部区域信息，为视线估计系统集成提供了可用技术基础[12,13]。

在系统应用方面，WebGazer 等工作展示了利用普通摄像头和用户交互数据进行网页端视线估计的可行性[14]。这类系统型研究说明，视线追踪不应仅被看作模型回归问题，还需要结合用户校准、交互反馈和部署环境。对于实时交互系统，时序稳定处理也十分重要。One Euro Filter 等面向交互系统的低通滤波方法体现了在噪声抑制和响应速度之间取得平衡的必要性[15]。

国内研究中，眼动跟踪技术综述、基于特征的视线跟踪方法研究、人机交互应用和非接触动态实时视线跟踪等工作，分别从技术发展、传统方法、应用场景和实时系统角度对相关问题进行了讨论[1,2,16,17]。近年来，端到端帧到视线估计等研究进一步探索从图像序列直接预测视线信息的可能性[18]。总体来看，视线估计技术已经具备较丰富的研究基础，但面向普通桌面摄像头的可运行交互系统仍需要在算法、几何、校准和软件集成之间进行综合设计。

## 1.3 课题问题定义与技术难点

本文研究的问题可以定义为：在普通 Windows 计算机和 RGB 摄像头条件下，实时估计用户在屏幕上的注视点，并将该注视点用于可视化验证和基础交互。

设第 (t) 帧摄像头图像为 (\mathbf{I}_t)，系统目标是估计屏幕注视点：

[
\hat{\mathbf{p}}_t=
\begin{bmatrix}
\hat{x}_t\
\hat{y}_t
\end{bmatrix}
]

（1-1）

其中，(\hat{x}_t) 和 (\hat{y}_t) 分别表示第 (t) 帧预测注视点在屏幕坐标系中的横向和纵向像素坐标。对于 Deep 路线，系统首先估计相机坐标系下的三维视线方向：

[
\hat{\mathbf{g}}*t=
\begin{bmatrix}
\hat{g}*{x,t}\
\hat{g}*{y,t}\
\hat{g}*{z,t}
\end{bmatrix},\qquad
|\hat{\mathbf{g}}_t|_2=1
]

（1-2）

随后通过屏幕几何映射得到原始屏幕点，并通过用户校准和平滑处理得到最终输出：

[
\hat{\mathbf{p}}_t^{final}
==========================

S
\left(
C
\left(
G(\hat{\mathbf{g}}_t)
\right)
\right)
]

（1-3）

其中，(G(\cdot)) 表示三维视线方向到屏幕平面的几何映射，(C(\cdot)) 表示用户校准映射，(S(\cdot)) 表示时序平滑处理。对于 Classic 路线，系统从眼区图像中提取原始二维特征点，再通过校准和平滑得到最终屏幕点。

围绕上述问题，本文需要解决以下技术难点。

第一，普通摄像头图像质量不稳定。摄像头分辨率、曝光、噪声、光照、模糊和眼镜反光都会影响人脸关键点检测和眼区图像质量。系统必须具备眼区裁剪、有效帧判断和检测失败容错能力。

第二，跨用户和跨设备差异明显。不同用户眼部结构、眼睑遮挡、虹膜颜色、佩戴眼镜情况和使用姿态差异较大，不同设备摄像头位置、屏幕尺寸和分辨率也不一致。模型需要具备一定泛化能力，同时系统需要通过校准修正个体和设备偏差。

第三，三维视线到屏幕坐标的映射存在几何误差。普通桌面环境通常没有精确相机内参和摄像头外参，屏幕距离和摄像头位置只能近似设置。即使三维方向估计较准，映射到屏幕像素坐标时仍可能产生较大误差。

第四，校准精度和用户负担之间存在矛盾。校准点越多，屏幕覆盖越完整，但用户负担越高；校准点越少，使用更方便，但映射稳定性可能下降。系统需要在工程可用性和误差修正能力之间取得平衡。

第五，实时交互对稳定性要求较高。逐帧注视点容易抖动，直接驱动光标会影响用户体验。系统需要通过平滑和停留触发等方式提高交互稳定性，同时避免过强平滑造成明显延迟。

## 1.4 本文研究内容

围绕普通 RGB 摄像头实时视线追踪与注视交互任务，本文主要开展以下研究工作。

第一，设计并实现 Look2Act 实时视线追踪软件系统。系统面向 Windows 桌面端，包含启动配置、摄像头预览、校准、实时追踪、全屏验证、交互启动器和五子棋演示等页面，支持 Classic 与 Deep 两种运行模式，并能够以本地可执行程序方式运行。

第二，构建自建视线数据集并完成预处理流程。本文设计了 5×5 屏幕目标点采集方案，采集用户注视屏幕目标点时的眼区图像、头姿信息、屏幕标签和设备信息。最终数据集包含 31 名用户、16 台设备和 7395 条有效样本。出于隐私和授权考虑，数据集仅用于本课题训练与评估，不作为公开数据集发布。预处理阶段完成有效样本筛选、左右眼图像提取、屏幕坐标归一化和三维视线方向标签构造。

第三，设计并训练 GazeNetV2 深度视线估计模型。模型采用左右眼共享卷积特征提取结构，融合头部姿态输入，输出三维视线方向单位向量。训练阶段使用角度损失优化预测方向与真实方向之间的夹角，部署阶段将训练完成的模型导出为 ONNX 格式，用于本地实时推理。

第四，实现传统视觉与深度学习双模式追踪框架。Classic 模式基于眼区暗色区域特征提取和用户校准映射实现注视点估计；Deep 模式基于 GazeNetV2 输出三维视线方向，并通过屏幕几何求交、用户校准和平滑处理得到最终注视点。两种模式共用软件界面、校准流程、验证流程和交互模块。

第五，完成注视点映射、校准、平滑和交互实现。系统通过三维射线与屏幕平面求交将 Deep 模式的视线方向转换为原始屏幕点，并通过 25 点校准修正系统误差。系统还加入时序平滑处理，降低注视点抖动，并通过停留触发方式实现基础注视交互。

第六，进行模型评估和系统测试。本文通过固定测试集评估、31 名用户留一交叉验证、校准映射实验、头姿消融分析、双模式系统表现分析、功能测试和实时性测试，对 Look2Act 的模型性能和系统可用性进行综合评价。

## 1.5 本文主要工作与特色

本文的主要工作和特色体现在以下几个方面。

第一，完成了从数据采集到注视交互的完整软件链路。与只关注离线模型训练不同，本文实现了摄像头输入、人脸检测、眼区裁剪、视线估计、屏幕映射、用户校准、时序平滑、全屏验证和交互演示的完整系统流程。系统能够以本地软件形式运行，符合工程设计类课题的软件成果要求。

第二，构建了面向真实桌面场景的自建数据集。数据集覆盖多用户、多设备和真实普通摄像头环境，能够支撑深度模型训练、固定划分测试和跨用户泛化实验。采集阶段采用隐私保护图像组织方式，避免保存完整人脸图像，降低数据处理中的隐私风险。

# 第二章 相关技术基础

## 2.1 本章概述

实时视线追踪系统涉及计算机视觉、深度学习、三维几何、人机交互和软件工程等多个方面。对于基于普通 RGB 摄像头的桌面视线追踪任务而言，系统不仅需要从眼部图像中估计用户视线方向，还需要将视线方向转换为屏幕注视点，并进一步通过用户校准和平滑处理满足实时交互需求。因此，在进行系统设计和算法实现之前，需要明确视线追踪的基本概念、常见方法、坐标关系和评价指标。

本章首先介绍视线追踪技术的基本定义和输出形式，然后分析传统几何方法、基于特征的方法和基于外观的深度学习方法。随后，介绍人脸关键点检测、眼区图像裁剪、头部姿态估计、三维视线方向表示、屏幕几何映射、用户校准和平滑滤波等关键技术。上述内容为后续 Look2Act 系统总体设计、GazeNetV2 模型构建、注视点映射与系统测试提供理论基础。

## 2.2 视线追踪基本概念

视线追踪是指通过采集和分析人眼、面部或头部运动状态，估计用户注视方向或注视点位置的技术。根据输出形式不同，视线追踪任务通常可以分为两类：一类是视线方向估计，即预测用户视线在二维或三维空间中的方向；另一类是注视点估计，即预测用户在屏幕、场景图像或真实空间中的注视位置。

在桌面计算机应用中，系统最终关注的是屏幕注视点。设屏幕注视点为：

[
\mathbf{p}=
\begin{bmatrix}
x\
y
\end{bmatrix}
]

（2-1）

其中，(x) 和 (y) 分别表示屏幕坐标系下的横向和纵向像素坐标。屏幕坐标系通常以屏幕左上角为原点，(x) 轴向右，(y) 轴向下。

对于三维视线估计任务，视线方向通常表示为三维单位向量：

[
\mathbf{g}=
\begin{bmatrix}
g_x\
g_y\
g_z
\end{bmatrix},\qquad
|\mathbf{g}|_2=1
]

（2-2）

其中，(\mathbf{g}) 表示相机坐标系或头部坐标系中的视线方向。三维视线方向本身不是屏幕坐标，需要结合屏幕平面模型、相机与屏幕之间的几何关系以及用户校准结果，才能得到最终屏幕注视点。

【图2-1占位：视线方向与屏幕注视点概念示意图。图中应包含用户眼睛、相机坐标系、三维视线方向、屏幕平面和二维注视点。】

图2-1 视线方向与屏幕注视点关系示意

从硬件条件看，视线追踪系统可以分为专用眼动仪系统和普通摄像头系统。专用眼动仪通常使用红外光源、红外摄像头和角膜反射点检测方法，能够在受控条件下取得较高精度，但设备成本较高、部署复杂。普通 RGB 摄像头系统不依赖专用硬件，部署成本低，更适合桌面软件、移动终端和低成本交互场景，但会受到光照、摄像头质量、头部姿态、用户差异和标定误差影响。

本文研究的 Look2Act 系统属于基于普通 RGB 摄像头的非接触式视线追踪系统，其目标是在普通 Windows 计算机和常见摄像头条件下，估计屏幕注视点并实现基础注视交互。

## 2.3 视线估计方法分类

基于视觉的视线估计方法大致可以分为基于几何模型的方法、基于图像特征的方法和基于外观的深度学习方法。三类方法在输入形式、标定需求、计算复杂度和适用场景上存在明显差异。

### 2.3.1 基于几何模型的方法

基于几何模型的方法通常通过建立眼球、瞳孔、角膜、相机和屏幕之间的空间几何关系来估计视线。专用眼动仪中常见的瞳孔中心—角膜反射方法就属于此类。该方法通过红外光源在角膜上形成反射点，并结合瞳孔中心位置推算视线方向。

几何模型方法的优点是物理意义明确，在硬件条件受控、光源稳定和标定充分的情况下能够取得较高精度。其缺点是对设备条件依赖较强，通常需要红外光源、较高质量的相机和较精确的标定过程。对于普通 RGB 摄像头系统，角膜反射点不可稳定获得，眼球三维模型参数也难以精确估计，因此完整几何模型方法难以直接应用。

### 2.3.2 基于图像特征的方法

基于图像特征的方法从眼区图像中提取瞳孔中心、虹膜边界、眼角位置、眼睑轮廓或暗色区域质心等特征，再通过回归模型或校准映射估计注视点。该类方法不一定依赖深度学习模型，通常具有计算量小、实现简单和处理过程可解释等特点。

对于普通摄像头条件下的桌面系统，基于图像特征的方法可以作为轻量级实现路线。例如，可以通过灰度化、阈值分割、形态学处理和轮廓矩计算眼区暗色区域中心，并将该特征点通过用户校准映射到屏幕坐标。此类方法的主要限制在于对光照、眼镜反光、瞳孔可见性、眼区裁剪质量和用户个体差异较敏感。当眼区图像质量较差或瞳孔边界不清时，特征点可能不稳定。

### 2.3.3 基于外观的深度学习方法

基于外观的深度学习方法直接从眼部图像、人脸图像或全脸图像中学习视线表示。与手工特征方法不同，外观方法不需要显式检测瞳孔中心或角膜反射点，而是通过卷积神经网络从图像纹理、眼睑形状、虹膜位置和面部上下文中学习映射关系。MPIIGaze、UnityEyes、全脸外观估计、RT-GENE 和 Gaze360 等数据集与模型推动了普通摄像头视线估计的发展[3-8]。

外观方法的优点是表达能力较强，能够在一定程度上适应复杂眼部外观和头部姿态变化。其缺点是依赖训练数据覆盖，跨用户、跨设备和跨环境泛化仍然困难。即使模型在离线测试集上取得较低角度误差，实时应用中仍需要解决屏幕几何映射、用户校准、时序稳定和交互可用性等问题。

三类方法对比如表2-1所示。

**表2-1 视线估计方法分类对比**

| 方法类型     | 主要输入              | 优点              | 局限性               | 适用场景            |
| -------- | ----------------- | --------------- | ----------------- | --------------- |
| 几何模型方法   | 瞳孔中心、角膜反射点、相机标定参数 | 物理意义明确，受控条件下精度高 | 依赖专用硬件和精确标定       | 红外眼动仪、实验室测量     |

Look2Act 系统同时实现了传统视觉路线和深度学习路线。Classic 模式对应基于图像特征的传统方法，Deep 模式对应基于外观的深度学习方法。两种方法在同一软件框架下共用校准、验证和交互模块。

## 2.4 基于外观的视线估计

### 2.4.1 眼区输入与全脸输入

基于外观的视线估计可以根据输入区域不同分为眼区输入、脸部输入和全脸输入。眼区输入只使用左眼、右眼或双眼图像，能够聚焦与视线方向最直接相关的局部区域，模型规模通常较小。全脸输入则利用脸部姿态、眼睛相对位置和面部上下文信息，能够在头部姿态变化较大时提供更多辅助信息[6]。

眼区输入的优点是隐私风险相对较低、输入尺寸较小、推理速度较快，适合实时桌面应用。其不足是缺少完整头部姿态和面部上下文，需要额外引入头姿估计或校准模块弥补。全脸输入包含更多上下文，但对隐私、计算量和数据规模提出更高要求。

Look2Act 的 Deep 路线采用左右眼图像作为主要视觉输入，并融合头姿向量作为辅助信息。该设计在模型轻量化、隐私保护和几何解释性之间取得折中。

### 2.4.2 二维注视点回归与三维视线方向回归

深度学习视线估计的输出形式可以是二维屏幕注视点，也可以是三维视线方向。二维注视点回归直接预测屏幕归一化坐标：

[
\hat{\mathbf{p}}=
\begin{bmatrix}
\hat{x}_n\
\hat{y}_n
\end{bmatrix}
]

（2-3）

这种方式结构简单，能够直接得到屏幕位置。但二维输出通常与特定屏幕分辨率、摄像头位置和用户坐姿强相关，跨设备和跨场景泛化难度较大。

三维视线方向回归则输出单位方向向量：

[
\hat{\mathbf{g}}=
\begin{bmatrix}
\hat{g}_x\
\hat{g}_y\
\hat{g}_z
\end{bmatrix}
]

（2-4）

该向量需要结合屏幕几何模型进一步转换为屏幕点。三维输出的优势在于物理意义更明确，能够将模型学习与屏幕几何映射分离，有利于分析误差来源。其不足是系统实现更复杂，需要处理坐标系、屏幕平面、射线求交和用户校准等问题。

本文的 Deep 路线采用三维视线方向回归。该设计使模型输出能够与后续几何映射和校准模块衔接，也便于从系统角度分析模型误差、几何误差和校准误差之间的关系。

### 2.4.3 角度误差评价

三维视线方向估计通常使用角度误差作为评价指标。设预测方向为 (\hat{\mathbf{g}})，真实方向为 (\mathbf{g})，二者均为单位向量，则角度误差为：

[
\theta=
\arccos
\left(
\operatorname{clamp}
\left(
\hat{\mathbf{g}}\cdot\mathbf{g},-1,1
\right)
\right)
]

（2-5）

其中，(\cdot) 表示向量点积。角度误差通常以度为单位：

[
\theta_{deg}=\theta\cdot\frac{180}{\pi}
]

（2-6）

角度误差可以反映三维方向预测是否准确，但不能完全代表屏幕交互效果。因为同样的角度误差在不同屏幕距离、不同屏幕尺寸和不同注视区域下可能对应不同像素偏差。因此，在桌面应用中还需要使用屏幕像素误差、校准后误差和交互成功率等指标综合评价。

## 2.5 人脸关键点检测与眼区裁剪

### 2.5.1 人脸关键点检测

人脸关键点检测是普通摄像头视线追踪系统的前置环节。系统需要从摄像头图像中定位人脸区域、眼部位置和用于头姿估计的关键点。常见关键点包括眼角、鼻尖、下巴、嘴角和人脸轮廓点。现代实时人脸关键点检测方法能够在普通摄像头视频流中提供较稳定的面部几何信息[12,13]。

在视线追踪系统中，人脸关键点主要有三种作用。第一，用于裁剪左右眼区域，得到深度模型或传统视觉方法的输入。第二，用于估计头部姿态，为三维几何映射提供辅助信息。第三，用于判断当前帧是否有效，例如是否检测到人脸、眼区是否越界、关键点质量是否足够等。

【图2-2占位：人脸关键点与眼区裁剪示意图。图中应标注眼角、鼻尖、嘴角、下巴、左右眼 ROI 和头姿估计关键点。】

### 2.5.2 眼区裁剪与标准化

眼区裁剪是将摄像头原始帧转换为模型输入的重要步骤。设原始图像为 (\mathbf{F})，左眼和右眼区域分别为 (\Omega_L) 和 (\Omega_R)，则裁剪后的眼区图像为：

[
\mathbf{E}_L=\mathbf{F}(\Omega_L)
]

（2-7）

[
\mathbf{E}_R=\mathbf{F}(\Omega_R)
]

（2-8）

裁剪后的眼区图像通常需要进行尺寸统一、颜色空间转换、归一化和张量格式转换。例如，在深度学习模型中，可以将左右眼图像统一为 (3\times128\times128) 的 RGB 张量。眼区标准化能够减少摄像头分辨率和人脸尺度变化带来的输入差异。

眼区裁剪质量会直接影响视线估计结果。如果裁剪区域过小，可能缺失眼角或眼睑信息；如果裁剪区域过大，则会引入过多背景和无关面部纹理。对于传统视觉方法，眼区裁剪还会影响瞳孔或暗色区域检测的稳定性。对于深度学习方法，眼区裁剪不稳定会使模型输入分布偏离训练数据，从而增加预测误差。

## 2.6 头部姿态估计

### 2.6.1 头姿表示

头部姿态描述用户头部相对于摄像头的方向变化，通常使用 yaw、pitch 和 roll 三个欧拉角表示。其中，yaw 表示左右转头，pitch 表示抬头或低头，roll 表示头部侧倾。头部姿态会显著影响眼部外观和视线方向，因此是普通摄像头视线追踪系统中的重要因素。

设头姿向量为：

[
\mathbf{h}=
\begin{bmatrix}
yaw\
pitch\
roll
\end{bmatrix}
]

（2-9）

在深度模型中，头姿向量可以作为辅助输入与眼部图像特征融合；在几何映射中，头姿还可以用于将头部坐标系下的视线方向转换到相机坐标系中。

### 2.6.2 PnP 头姿求解

PnP，即 Perspective-n-Point，是根据三维点和二维图像投影点之间的对应关系求解相机或物体姿态的方法。在头姿估计中，可以使用预定义的三维人脸模型点和检测到的二维人脸关键点建立对应关系。

设第 (i) 个三维人脸模型点为 (\mathbf{X}_i)，其二维图像点为 (\mathbf{u}_i=(u_i,v_i)^T)，相机内参矩阵为 (K)，旋转矩阵为 (R)，平移向量为 (t)，则投影关系为：

[
s_i
\begin{bmatrix}
u_i\
v_i\
1
\end{bmatrix}
=============

K
\left(
R\mathbf{X}_i+t
\right)
]

（2-10）

其中，(s_i) 为尺度因子。通过多个点的对应关系，可以求解旋转矩阵和平移向量，并进一步转换为 yaw、pitch、roll。

【图2-3占位：PnP 头姿估计示意图。图中应包含三维人脸模型点、二维关键点、相机坐标系、旋转矩阵和平移向量。】

图2-3 PnP 头部姿态估计示意

需要注意的是，普通摄像头系统通常缺少精确相机内参，三维人脸模型也只是简化近似，因此 PnP 头姿结果可能存在误差。若将不稳定的头姿估计直接用于三维坐标变换，可能引入新的系统偏差。因此，在实际系统中，头姿既可以作为模型输入或辅助分析变量，也需要结合坐标约定和实验结果谨慎使用。

## 2.7 三维视线与屏幕几何映射

### 2.7.1 相机坐标系与屏幕坐标系

三维视线方向需要通过几何映射转换为屏幕二维注视点。该过程涉及相机坐标系、屏幕三维平面和屏幕像素坐标系。

在相机坐标系中，通常约定 (X) 轴指向图像右侧，(Y) 轴指向图像下方，(Z) 轴指向摄像头前方。屏幕可以近似为相机坐标系中的一个平面。屏幕像素坐标系则以屏幕左上角为原点，(x) 轴向右，(y) 轴向下。

若模型输出的是相机坐标系下的三维视线方向，则可以直接构造相机空间中的视线射线；若模型输出的是头部坐标系下的方向，则还需要通过头姿旋转矩阵将其转换到相机坐标系。

### 2.7.2 射线与屏幕平面求交

设视线射线原点为 (\mathbf{o})，视线方向为单位向量 (\mathbf{d})，则三维射线可以表示为：

[
\mathbf{P}(\lambda)=\mathbf{o}+\lambda\mathbf{d}
]

（2-11）

其中，(\lambda) 为射线参数。设屏幕平面上一点为 (\mathbf{p}_0)，屏幕平面法向量为 (\mathbf{n})，则屏幕平面方程为：

[
\mathbf{n}\cdot(\mathbf{p}-\mathbf{p}_0)=0
]

（2-12）

将射线方程代入平面方程，可得到：

[
\lambda=
\frac{\mathbf{n}\cdot(\mathbf{p}_0-\mathbf{o})}
{\mathbf{n}\cdot\mathbf{d}}
]

（2-13）

当 (\mathbf{n}\cdot\mathbf{d}) 接近零时，视线射线与屏幕平面近似平行，交点不稳定；当 (\lambda<0) 时，交点位于射线反方向，不应作为有效注视点。若交点有效，则三维交点为：

[
\mathbf{p}=\mathbf{o}+\lambda\mathbf{d}
]

（2-14）

### 2.7.3 三维交点到屏幕像素坐标

得到屏幕平面上的三维交点后，需要将其转换为屏幕像素坐标。设屏幕左上角对应三维点为 (\mathbf{p}_{tl})，屏幕水平和竖直方向单位向量分别为 (\mathbf{e}_x) 和 (\mathbf{e}_y)，则交点在屏幕平面上的物理坐标为：

[
x_{mm}=(\mathbf{p}-\mathbf{p}_{tl})\cdot\mathbf{e}_x
]

（2-15）

[
y_{mm}=(\mathbf{p}-\mathbf{p}_{tl})\cdot\mathbf{e}_y
]

（2-16）

设屏幕物理宽度和高度分别为 (W_{mm}) 和 (H_{mm})，屏幕像素宽度和高度分别为 (W_{px}) 和 (H_{px})，则像素坐标为：

[
x_{px}=\frac{x_{mm}}{W_{mm}}W_{px}
]

（2-17）

[
y_{px}=\frac{y_{mm}}{H_{mm}}H_{px}
]

（2-18）

上述过程为三维视线方向到屏幕注视点的基本几何链路。实际系统中，由于摄像头位置、屏幕距离、相机内参和用户坐姿通常只是近似已知，因此几何映射结果仍需要用户校准进一步修正。

## 2.8 用户校准技术

### 2.8.1 校准的作用

用户校准是普通摄像头视线追踪系统中的关键环节。即使视线模型能够较准确地预测方向，系统仍会受到用户眼部结构、摄像头安装位置、屏幕参数和坐姿差异影响，导致屏幕注视点存在系统性偏差。校准的目标是建立原始输出与真实屏幕目标点之间的映射关系，从而修正个体和设备偏差。

设第 (i) 个校准样本的原始输出点为 (\mathbf{p}_i^{raw})，真实目标点为 (\mathbf{p}_i^{target})，校准映射函数为 (h(\cdot))，则校准目标可以表示为：

[
h^*=
\arg\min_h
\sum_{i=1}^{N}
\left|
h(\mathbf{p}_i^{raw})
---------------------

\mathbf{p}_i^{target}
\right|_2^2
]

（2-19）

其中，(N) 为校准样本数量。校准点数量越多，屏幕覆盖越完整，但用户负担也越大。因此，校准策略需要在精度、稳定性和易用性之间取得平衡。CalibMe 和少样本个性化等研究也说明，校准和个性化仍是实际 gaze interaction 系统中的重要问题[9,10]。

### 2.8.2 仿射校准

仿射映射可以表达平移、缩放、旋转和剪切等线性变换。设原始点为 ((x,y))，校准后点为 ((x',y'))，则仿射映射为：

[
\begin{bmatrix}
x'\
y'
\end{bmatrix}
=============

A
\begin{bmatrix}
x\
y\
1
\end{bmatrix}
]

（2-20）

其中，(A\in\mathbb{R}^{2\times3}) 为待求参数矩阵。仿射映射参数较少，对少量校准点较稳定，适合快速校准和线性偏差修正。

### 2.8.3 多项式校准

当校准点较多且屏幕覆盖较完整时，可以使用多项式映射表达非线性偏差。二阶多项式特征可写为：

[
\boldsymbol{\phi}(x,y)=
\begin{bmatrix}
x\
y\
xy\
x^2\
y^2\
1
\end{bmatrix}
]

（2-21）

对应映射为：

[
\begin{bmatrix}
x'\
y'
\end{bmatrix}
=============

W\boldsymbol{\phi}(x,y)
]

（2-22）

其中，(W\in\mathbb{R}^{2\times6}) 为参数矩阵。多项式映射表达能力更强，但参数更多，在校准点少或采样噪声较大时可能出现过拟合。因此，在实际系统中需要根据校准点数量、采样质量和验证误差选择合适映射方式。

## 2.9 时序平滑与交互稳定性

### 2.9.1 注视点抖动问题

实时视线追踪输出通常存在帧间抖动。抖动来源包括摄像头图像噪声、人脸关键点检测误差、眼区裁剪误差、模型推理误差、头部微小运动和校准映射放大效应。如果直接将逐帧输出显示为光标，用户会感受到明显不稳定，影响全屏验证和注视交互。

因此，实时系统通常需要对注视点进行时序平滑。平滑的目标是在降低抖动的同时尽量保持响应速度。对于注视交互任务，平滑过弱会导致误触发，平滑过强则会导致光标滞后。

### 2.9.2 指数滑动平均

指数滑动平均是一种简单有效的低通滤波方法。设当前输入点为 (\mathbf{x}*t)，上一帧平滑结果为 (\mathbf{s}*{t-1})，当前平滑输出为 (\mathbf{s}_t)，则有：

[
\mathbf{s}_t=
\alpha\mathbf{x}*t+(1-\alpha)\mathbf{s}*{t-1}
]

（2-23）

其中，(\alpha\in(0,1]) 为平滑系数。当 (\alpha) 较大时，输出更接近当前输入，响应速度较快；当 (\alpha) 较小时，输出更平稳，但延迟增加。One Euro Filter 等方法进一步尝试根据运动速度动态调整低通滤波强度，以兼顾快速移动和稳定注视状态[15]。

### 2.9.3 Kalman 滤波

Kalman 滤波是一种基于状态空间模型的递推估计方法，适合处理带噪声的动态系统。对于二维注视点，可以将状态定义为位置和速度：

[
\mathbf{x}*t=
\begin{bmatrix}
x_t\
y_t\
v*{x,t}\
v_{y,t}
\end{bmatrix}
]

（2-24）

其状态转移可写为：

[
\mathbf{x}*t=F\mathbf{x}*{t-1}+\mathbf{w}_t
]

（2-25）

观测方程为：

[
\mathbf{z}_t=H\mathbf{x}_t+\mathbf{v}_t
]

（2-26）

其中，(\mathbf{w}_t) 和 (\mathbf{v}_t) 分别表示过程噪声和观测噪声。Kalman 滤波能够结合运动模型和观测结果，对注视点进行平滑估计。但其参数设置较指数滑动平均更复杂，需要根据实际系统噪声特性调整。

### 2.9.4 停留触发与 Midas Touch 问题

注视交互中存在一个典型问题：用户看向某个目标并不一定意味着要触发操作。如果系统将所有注视都解释为点击，会产生大量误触发，这一问题通常被称为 Midas Touch 问题。为缓解该问题，注视交互系统常采用停留触发方式，即只有当注视点在目标区域内持续停留超过阈值时才触发操作。

设目标区域为 (\mathcal{R})，注视点为 (\mathbf{p}_t)，则目标命中状态为：

[
\delta_t=
\begin{cases}
1, & \mathbf{p}_t\in\mathcal{R}\
0, & \mathbf{p}_t\notin\mathcal{R}
\end{cases}
]

（2-27）

当连续命中时间达到阈值 (T_d) 时，系统触发交互事件。停留触发适合大目标选择、菜单启动和简单桌面交互，但不适合高频小目标点击任务。因此，普通摄像头视线交互系统通常更适合注视点可视化、大目标选择和辅助输入原型，而不是直接替代鼠标完成精细操作。WebGazer 等系统型工作也表明，基于普通摄像头的 gaze interaction 需要将模型估计、校准和交互设计结合起来考虑[14]。

## 2.10 视线追踪系统评价指标

视线追踪系统的评价不能只依赖单一指标，外观式视线估计在应用场景中的表现还需要结合校准、距离、环境条件和交互任务综合分析[11]。对于深度模型，需要评价角度误差；对于屏幕注视点，需要评价像素误差；对于交互系统，还需要评价实时性、稳定性和可用性。

### 2.10.1 像素误差

设预测屏幕点为 (\hat{\mathbf{p}})，真实目标点为 (\mathbf{p})，则像素误差为：

[
e_{px}=
\left|
\hat{\mathbf{p}}-\mathbf{p}
\right|_2
]

（2-28）

像素误差越小，预测点越接近真实目标点。像素误差与屏幕分辨率有关，因此在跨设备比较时需要结合屏幕尺寸和目标大小共同分析。

### 2.10.2 实时性指标

实时性通常使用帧率和延迟衡量。设系统在时间窗口 (\Delta T) 内处理帧数为 (N_f)，则平均帧率为：

[
FPS=\frac{N_f}{\Delta T}
]

（2-29）

端到端延迟包括摄像头采集、图像处理、模型推理、校准映射、平滑处理和界面绘制等阶段。对于交互系统而言，帧率和延迟会直接影响用户体验。

### 2.10.3 稳定性指标

稳定性可以通过注视点抖动衡量。设稳定注视状态下第 (t) 帧注视点为 (\mathbf{p}_t)，序列均值为 (\bar{\mathbf{p}})，则抖动均方根可表示为：

[
J_{rms}=
\sqrt{
\frac{1}{T}
\sum_{t=1}^{T}
\left|
\mathbf{p}_t-\bar{\mathbf{p}}
\right|_2^2
}
]

（2-30）

该指标越小，说明注视点在稳定注视状态下越平稳。对于停留触发交互，稳定性通常比瞬时峰值精度更重要。

### 2.10.4 交互可用性指标

交互可用性可以通过任务成功率、完成时间和误触发次数衡量。设某一交互任务共进行 (N) 次试验，成功完成 (N_s) 次，则成功率为：

[
R_s=\frac{N_s}{N}
]

（2-31）

若第 (i) 次成功任务完成时间为 (T_i)，则平均完成时间为：

[
\bar{T}=
\frac{1}{N_s}
\sum_{i=1}^{N_s}T_i
]

（2-32）

对于本文系统而言，模型角度误差、屏幕像素误差、帧率、校准后表现和交互成功情况需要共同分析，才能较全面评价 Look2Act 的实际可用性。

## 2.11 本章小结

本章介绍了实时视线追踪系统涉及的相关技术基础。首先，说明了视线方向和屏幕注视点的基本概念，明确了三维视线向量与二维屏幕坐标之间的区别。随后，分析了基于几何模型、基于图像特征和基于外观深度学习的视线估计方法，指出普通 RGB 摄像头系统需要在低成本硬件条件下处理光照、头姿、用户差异和设备差异等问题。

在视觉处理方面，本章介绍了人脸关键点检测、眼区裁剪和头部姿态估计。人脸关键点用于眼区定位和 PnP 头姿求解，眼区裁剪为传统视觉方法和深度学习模型提供输入，头姿信息则为模型融合和几何分析提供辅助。随后，本章给出了三维视线射线与屏幕平面求交的基本数学过程，并说明了三维交点到屏幕像素坐标的转换方法。

在系统实现方面，本章介绍了用户校准、时序平滑、停留触发和系统评价指标。校准用于修正用户差异和设备几何误差，平滑用于降低帧间抖动，停留触发用于缓解注视交互中的误触发问题。评价指标方面，角度误差、像素误差、帧率、抖动和交互成功率需要共同使用，才能反映普通摄像头视线追踪系统的整体性能。

# 第三章 Look2Act 系统总体设计

## 3.1 系统设计目标与需求分析

本课题面向普通 Windows 计算机和标准 RGB 摄像头，设计并实现一套实时视线追踪与注视交互系统。系统目标是在不依赖红外眼动仪、专用光源和专用追踪硬件的条件下，通过摄像头图像估计用户注视位置，并将视线信息用于屏幕注视点可视化、全屏验证和注视交互演示。

Look2Act 系统的设计重点不是单一算法模块，而是从数据采集、模型训练、实时推理、屏幕映射、用户校准、时序平滑到交互应用的完整软件链路。系统既需要完成深度学习视线估计模型的训练与部署，也需要保证软件能够在普通桌面环境中稳定运行。因此，本文将 Look2Act 定位为工程设计类软件系统，系统实现和算法研究共同构成论文主体。

从用户角度看，系统需要完成以下功能：启动程序后能够选择运行模式；能够打开摄像头并显示实时预览；能够检测人脸和眼部区域；能够完成用户校准；能够在屏幕上显示估计注视点；能够进入全屏验证页面检查追踪效果；能够通过注视光标和停留触发完成基础交互任务。

从技术角度看，系统需要完成以下任务：对摄像头图像进行逐帧处理；提取人脸关键点和眼区图像；估计头部姿态；实现传统计算机视觉和深度学习两种视线估计路线；将原始视线结果映射为屏幕坐标；通过多点校准修正用户差异、设备差异和几何近似误差；通过平滑算法降低帧间抖动；最终将注视点输出给验证界面和交互界面。

从工程角度看，系统需要满足实时性、稳定性、可配置性和可部署性要求。实时性要求系统能够持续处理摄像头视频帧，并以可接受的刷新频率输出注视点；稳定性要求系统在短时检测失败、眼区异常或注视点突变时具备容错能力；可配置性要求系统能够根据不同设备和运行场景调整摄像头、模型、几何参数、校准方式和平滑参数；可部署性要求系统能够通过 Windows 可执行程序运行，并将用户配置、校准结果等可变数据保存到用户可写目录中。

| 视觉处理需求 | 人脸检测、眼区裁剪、头姿估计   | 为视线估计和屏幕映射提供基础输入                                |
| 算法需求   | 支持传统视觉路线与深度学习路线  | Classic 模式实现传统图像处理路线，Deep 模式实现 GazeNetV2 深度学习路线 |
| 映射需求   | 将原始视线结果映射为屏幕坐标   | 结合几何映射和用户校准得到最终注视点                              |
| 校准需求   | 支持多点用户校准         | 修正用户差异、摄像头位置差异和屏幕几何误差                           |
| 交互需求   | 支持全屏验证和注视交互      | 实现注视光标、停留触发和交互演示                                |
| 部署需求   | 支持 Windows 桌面端运行 | 通过本地软件方式完成演示和测试                                 |
| 隐私需求   | 数据采集阶段避免保存完整人脸   | 采用眼区裁剪和隐私保护图像进行数据组织                             |

## 3.2 系统总体架构

Look2Act 系统采用分层式架构，整体流程包括数据采集、数据预处理、模型训练、实时追踪、校准验证和注视交互六个主要环节。系统由两个相互衔接的软件部分构成：其一是数据采集系统，用于采集用户注视屏幕目标点时的眼区图像、头姿信息、屏幕标签和设备信息；其二是 Look2Act Tracker，用于完成模型训练、实时推理、用户校准、结果验证和交互演示。

这种分离式设计有利于降低系统复杂度。数据采集系统面向数据提供者，重点是采集流程、标签记录和隐私保护；Tracker 系统面向研究和演示，重点是算法推理、软件界面、校准映射和交互输出。二者通过统一的数据格式连接，使数据采集、模型训练和实时部署之间形成清晰边界。

【图3-1占位：Look2Act 系统总体架构图。图中应包含数据采集系统、数据预处理、GazeNetV2 模型训练、模型导出、Classic/Deep 双模式追踪、校准、平滑、验证和交互界面等模块。】

图3-1 Look2Act 系统总体架构

从功能层次上看，Look2Act 可划分为以下六层。

第一层是数据采集层。该层通过独立采集程序显示屏幕目标点，并记录用户注视目标点时的图像、头姿、屏幕坐标和设备信息。采集结果用于构建训练集、验证集和测试集，为深度学习路线提供监督学习数据。

第二层是视觉感知层。该层以摄像头视频帧为输入，完成基础视觉处理，包括人脸关键点检测、左右眼区域裁剪、头姿估计所需关键点提取和眼区图像标准化。该层是 Classic 模式和 Deep 模式的公共基础。

第三层是视线估计层。Classic 模式基于传统图像处理方法提取眼区暗色区域或瞳孔近似中心，得到归一化眼部特征；Deep 模式基于 GazeNetV2 模型，从左右眼图像和姿态输入中回归三维视线方向向量。两种模式的估计方式不同，但最终都需要进入屏幕坐标映射阶段。

第四层是映射与校准层。该层负责将原始输出转换为屏幕注视点。对于 Classic 模式，系统通过校准映射将眼部特征点转换为屏幕坐标；对于 Deep 模式，系统先通过三维射线与屏幕平面求交获得原始屏幕点，再通过用户校准修正系统误差。校准模块是普通摄像头视线追踪系统中连接算法输出和真实屏幕坐标的重要环节。

第五层是时序稳定层。普通摄像头图像容易受到光照、模糊、检测误差和用户微小运动影响，逐帧注视点会产生抖动。系统通过指数滑动平均、Kalman 滤波或屏幕空间稳定策略降低帧间噪声，提高注视光标的连续性和可用性。

第六层是用户界面与交互层。该层通过桌面图形界面提供启动配置、摄像头预览、校准、追踪、验证和交互页面。系统输出的注视点不仅用于数值显示，也用于全屏验证、注视光标显示、停留触发和交互应用演示。

通过上述分层设计，Look2Act 将视线追踪问题拆解为视觉感知、模型估计、几何映射、个体校准和交互稳定等相互衔接的子问题。该设计有助于在系统调试和实验分析时定位误差来源，也便于后续替换模型、调整校准方式或扩展交互任务。

## 3.3 数据采集系统设计

为了训练和评估深度学习视线估计模型，本文设计了独立的数据采集系统。该系统运行于 Windows 桌面环境，通过摄像头采集用户注视屏幕目标点时的数据，并生成后续训练与评估所需的标签文件、元数据文件和隐私保护图像。

数据采集系统采用 5×5 网格目标点方案，共包含 25 个目标点。采集过程中，目标点以随机顺序显示在屏幕上。每个目标点显示固定时长，其中前一段时间作为注视稳定期，稳定期结束后按设定帧率保存有效样本。该方式能够覆盖屏幕中心、边缘和角落区域，使训练样本包含较完整的屏幕空间分布。

【图3-2占位：数据采集系统流程图。图中应包含用户配置、摄像头检查、人脸检测、5×5 目标点显示、有效帧判断、标签写入、隐私保护图像保存和采集结果打包等步骤。】

图3-2 数据采集系统流程

采集系统主要包括用户配置、采集检查、目标点采集和采集完成四个阶段。用户配置阶段记录用户编号、是否佩戴眼镜、摄像头设备和分辨率等信息；采集检查阶段显示实时检测状态，包括人脸是否检测成功、头姿估计是否有效、眼区质量是否满足要求；目标点采集阶段全屏显示红色目标点并保存有效帧；采集完成阶段统计有效帧数量、无效帧数量和采集结果，并生成便于后续处理的数据文件。

在隐私保护方面，采集系统不保存完整人脸图像，而是保存由左眼区域、右眼区域、标记区域和头姿轮廓区域组成的合成图。该设计既保留了模型训练所需的眼部信息，也降低了完整面部图像长期保存带来的隐私风险。由于数据仍包含真实用户眼部图像和设备信息，本文自建数据集仅用于本课题训练、评估和系统验证，不作为公开数据集发布。

## 3.5 Classic 与 Deep 双模式设计

Look2Act 设计了 Classic 与 Deep 两种运行模式。两种模式分别代表传统计算机视觉路线和深度学习视线估计路线。它们不是简单的主次关系，而是在同一系统框架下实现的两条互补方法路线。Classic 模式强调轻量、实时和可解释的传统视觉处理；Deep 模式强调基于监督学习的三维视线方向回归，是本文模型训练和算法分析的核心路线。

Classic 模式基于眼区图像处理实现。系统首先通过人脸关键点定位左右眼区域，然后对眼区图像进行灰度化、模糊、阈值分割、形态学处理和轮廓分析，提取暗色区域质心或瞳孔近似中心。随后，系统将左右眼特征转换到相机画面坐标，并融合得到归一化眼部特征点。该特征点本身并不是屏幕坐标，需要通过用户校准映射到屏幕位置。

Deep 模式基于 GazeNetV2 深度学习模型实现。系统从摄像头帧中提取左右眼图像，将其标准化为模型输入，并结合姿态输入通过模型回归三维视线方向单位向量。随后，系统根据三维射线与屏幕平面的几何关系计算原始屏幕注视点，并通过校准和平滑模块得到最终输出。Deep 模式是本文数据集构建、模型训练、固定划分测试和跨用户泛化分析的主要研究对象。

Classic 与 Deep 两种模式共用摄像头输入、人脸检测、用户界面、校准页面、验证页面和交互页面，但在视线估计后端、原始输出形式和误差来源上存在差异。两种模式的对比如表3-2所示。

**表3-2 Classic 模式与 Deep 模式对比**

| 对比项      | Classic 模式        | Deep 模式                |
| -------- | ----------------- | ---------------------- |
| 方法类型     | 传统计算机视觉方法         | 监督式深度学习方法              |
| 核心输入     | 左右眼 ROI、暗色区域或瞳孔特征 | 左右眼图像、姿态输入             |
| 是否需要模型训练 | 不需要               | 需要训练 GazeNetV2         |
| 原始输出     | 归一化眼部特征点          | 三维视线方向向量或几何映射后的原始屏幕点   |
| 屏幕映射方式   | 通过用户校准映射到屏幕坐标     | 通过几何求交和用户校准得到屏幕坐标      |
| 主要优势     | 结构轻量、计算开销小、过程可解释  | 表达能力较强，能够学习眼部外观与视线方向关系 |
| 主要限制     | 对光照、瞳孔可见性和个体差异敏感  | 对训练数据、坐标约定、几何参数和部署配置敏感 |
| 论文定位     | 传统视觉实现路线和系统对照路线   | 深度学习研究路线和模型训练核心路线      |

双模式设计具有三方面意义。第一，它使系统能够在同一套软件界面下展示传统视觉方法和深度学习方法的实际效果，增强系统完整性。第二，它使论文能够同时讨论传统图像处理、深度模型训练、屏幕映射和系统集成，而不是局限于单一模型指标。第三，它为实验分析提供了对照视角，有助于说明普通摄像头视线交互系统中的误差并不只来自模型本身，还来自眼区检测、几何映射、校准策略和时序稳定等多个环节。

Look2Act 系统按照功能职责划分为多个模块。各模块之间通过统一的数据结构传递中间结果，便于开发、调试和实验分析。主要功能模块见表3-3。

**表3-3 Look2Act 主要功能模块**

| 模块名称       | 主要功能                  | 输入           | 输出                     |
| ---------- | --------------------- | ------------ | ---------------------- |
| 配置管理模块     | 加载和保存系统配置             | YAML 配置、用户选择 | 系统配置对象                 |
| 摄像头输入模块    | 打开摄像头并读取视频帧           | 摄像头设备        | BGR 图像帧                |
| 人脸与眼区检测模块  | 检测人脸关键点并裁剪眼区          | 视频帧          | 左右眼图像、关键点、眼区 ROI       |

| Classic 后端 | 提取传统视觉眼部特征            | 左右眼 ROI      | 归一化眼部特征点               |

| 交互模块       | 实现注视光标和停留触发           | 注视点坐标        | 交互事件                   |

人脸与眼区检测模块是整个系统的基础。该模块不仅为 Classic 模式提供眼区 ROI，也为 Deep 模式提供模型输入图像，同时还为头姿估计模块提供关键点。人脸检测失败、眼区裁剪异常或关键点质量不足都会影响后续视线估计结果，因此系统在实时管线中加入了有效性判断和异常处理机制。

头姿估计模块用于分析用户头部相对摄像头的姿态变化。头部姿态信息可以作为深度模型输入，也可以用于三维几何映射和误差分析。由于普通摄像头缺少精确标定，头姿估计结果本身也可能带有误差，因此系统在部署配置中保留了姿态输入方式的可配置性。

校准模块是系统从“视线估计”走向“屏幕交互”的关键模块。无论 Classic 模式还是 Deep 模式，原始输出都难以直接成为准确的屏幕注视点。系统通过多点校准采集原始点与目标点之间的对应关系，并拟合映射函数修正系统偏差。最终系统采用 5×5 共 25 点校准流程，使校准点覆盖屏幕主要区域。

平滑模块用于提升交互体验。视线估计结果通常存在抖动，特别是在普通摄像头、自然光照和用户自然头动条件下，逐帧输出可能不稳定。系统通过平滑处理在响应速度和稳定性之间取得平衡。过强的平滑会造成注视光标延迟，过弱的平滑则会影响停留触发和目标选择的稳定性。

## 3.7 实时处理流程设计

Look2Act 的实时处理流程以摄像头视频帧为单位进行。每一帧图像进入系统后，首先完成人脸检测和眼区定位。若检测失败，系统根据上一帧有效结果进行容错处理，避免注视点突然消失或界面状态频繁跳变。若检测成功，系统根据当前运行模式进入不同后端。

Classic 模式下，系统对左右眼 ROI 进行传统图像处理，提取瞳孔或暗色区域中心，并将其转换为归一化眼部特征点。该特征点经过用户校准映射后得到屏幕注视点，再进入平滑和交互输出阶段。

Deep 模式下，系统先估计头部姿态并提取左右眼图像，然后将眼区图像转换为模型输入张量。GazeNetV2 输出三维视线方向向量后，系统根据屏幕几何参数构造三维射线，并计算射线与屏幕平面的交点。交点转换为屏幕像素坐标后，进入校准和平滑模块，最终输出给界面层。

```text
输入：摄像头图像帧 frame
输出：屏幕注视点 gaze_point

1. 对 frame 进行人脸关键点检测
2. 若未检测到有效人脸：
      返回上一帧有效结果或标记当前帧无效
3. 裁剪左右眼区域并提取头姿估计所需关键点
4. 若运行模式为 Classic：
      4.1 对左右眼 ROI 进行灰度化、阈值分割和轮廓分析
      4.2 提取暗色区域质心或瞳孔近似中心
      4.3 融合左右眼特征并生成原始特征点
5. 若运行模式为 Deep：
      5.1 将左右眼图像转换为模型输入张量
      5.2 构造姿态输入
      5.3 调用 GazeNetV2 得到三维视线方向
      5.4 计算视线射线与屏幕平面的交点
      5.5 将交点转换为原始屏幕坐标
6. 应用用户校准映射
7. 对连续注视点进行平滑处理
8. 输出最终屏幕注视点
```

该流程体现了系统的模块化特征。视觉检测、后端估计、几何映射、校准和平滑相互分离，使系统能够分别分析各阶段耗时和误差来源，也便于后续替换模型或调整校准策略。

# 第四章 数据集构建与深度视线估计模型

## 4.1 本章概述

实时视线追踪系统的性能不仅取决于模型结构，还与数据采集方案、标签构造方式、预处理流程、训练目标和实时部署接口密切相关。Look2Act系统面向普通Windows计算机和RGB摄像头，目标是在无需专用眼动仪的条件下估计用户在屏幕上的注视位置。因此，深度学习路线需要完成两个层面的任务：一是从眼部外观和辅助姿态信息中学习三维视线方向；二是使模型输出能够与后续屏幕几何映射、用户校准、时序平滑和交互界面自然衔接。

本章围绕Look2Act系统中的深度学习主线展开。首先介绍自建数据集的采集目标、采集流程、数据字段和隐私保护方案；随后说明从采集数据到训练样本的预处理过程，包括有效样本筛选、眼区图像提取、屏幕坐标归一化和三维视线标签构造；接着给出GazeNetV2模型的结构设计、输入输出定义、损失函数和训练策略；最后介绍模型保存、ONNX导出和实时推理接口。

在方法定位上，本文的Deep路线不直接回归某一屏幕分辨率下的二维像素坐标，而是回归相机坐标系下的三维视线方向单位向量。该设计使模型输出具有明确的几何含义，便于在后续章节中结合屏幕平面模型、校准映射和交互稳定策略完成完整的注视点估计链路。

## 4.2 自建数据集构建

### 4.2.1 数据采集目标

公开视线估计数据集为深度模型研究提供了重要基础，但其采集设备、屏幕布局、相机位置、使用距离和标注方式通常具有特定假设，与普通桌面应用场景之间仍存在差异[3-8]。Look2Act系统面向普通RGB摄像头和真实Windows桌面环境，因此需要构建贴近本课题应用条件的自建数据集，用于模型训练、误差分析和系统验证。

本课题数据采集主要服务于以下目标。第一，采集真实用户在普通摄像头条件下的眼区图像，使模型能够学习自然光照、不同摄像头质量、不同屏幕分辨率和不同用户眼部外观下的视线变化。第二，记录屏幕目标点、头部姿态、设备信息和采集质量指标，为后续训练、评估和误差归因提供数据基础。第三，在采集阶段控制隐私风险，不保存完整人脸图像，而是保存眼区裁剪图和必要的辅助区域信息。

最终自建数据集包含31名用户、16台设备和7395条有效样本。数据集覆盖不同摄像头、屏幕分辨率、使用距离和用户状态，为模型固定划分评估、跨用户泛化评估和系统级误差分析提供了基础。由于数据中包含真实用户眼部图像、设备信息和采集会话信息，本文仅使用该数据集进行课题内部训练与评估，不将其作为公开数据发布。

### 4.2.2 采集流程设计

数据采集由独立的桌面采集程序完成。采集时，程序通过全屏界面在屏幕上依次显示目标点，并同步记录摄像头图像、目标点坐标、人脸检测状态、头部姿态、设备信息和采集状态。采集目标采用5×5网格布局，共25个屏幕目标点。每个目标点显示2.0秒，其中前500 ms作为注视稳定期，稳定期之后按设定帧率保存有效数据。

【图4-1占位：数据采集界面与5×5目标点布局示意图。建议使用真实采集界面截图，标注目标点、稳定期、保存期、摄像头检测状态和隐私预览区域。】

采集流程分为配置、检查、采集和完成四个阶段。配置阶段用于填写用户编号、眼镜状态、摄像头设备和采集分辨率等信息；检查阶段用于确认人脸检测、头姿估计、眼区裁剪和采集质量是否正常；采集阶段全屏显示25个随机顺序目标点，并保存有效帧及其标签；完成阶段统计有效帧数量、无效帧数量和采集结果，并生成包含标签文件、元数据文件和隐私保护图像的采集包。

### 4.3.3 屏幕坐标归一化

采集系统记录的目标点为屏幕像素坐标。由于不同设备的屏幕分辨率可能不同，直接使用像素坐标不利于跨设备建模。因此，预处理阶段首先将目标点像素坐标归一化到([0,1]\times[0,1])的屏幕坐标空间。

设目标点像素坐标为((x,y))，屏幕宽度和高度分别为(W)和(H)，则归一化坐标为：

[
x_n=\frac{x}{W}
]

（4-2）

[
y_n=\frac{y}{H}
]

（4-3）

其中，(x_n)和(y_n)分别表示目标点在屏幕水平方向和竖直方向上的归一化位置。通过该处理，不同屏幕分辨率下的目标点能够进入统一坐标空间，为后续三维标签构造和跨设备训练提供基础。

### 4.3.4 三维视线方向标签构造

本文深度学习路线不直接以二维像素点作为模型输出，而是将屏幕目标点转换为相机坐标系下的三维视线方向单位向量。该设计使模型输出具有方向意义，并能够与后续屏幕几何映射过程连接。

设屏幕物理宽度为(W_{mm})，屏幕物理高度为(H_{mm})，相机到屏幕平面的近似距离为(d)，屏幕上边缘相对相机中心的竖直偏移量为(c_{top})。对于归一化目标点((x_n,y_n))，其对应的屏幕空间点可表示为：

[
X=x_nW_{mm}-\frac{W_{mm}}{2}
]

（4-4）

[
Y=c_{top}+y_nH_{mm}
]

（4-5）

[
Z=d
]

（4-6）

于是，从相机近似原点指向该屏幕目标点的未归一化方向向量为：

[
\tilde{\mathbf{g}}=
\begin{bmatrix}
X\
Y\
Z
\end{bmatrix}
]

（4-7）

最终三维视线方向标签定义为：

[
\mathbf{g}=\frac{\tilde{\mathbf{g}}}{|\tilde{\mathbf{g}}|_2}
]

（4-8）

其中，(|\cdot|_2)表示二范数，(\mathbf{g})为单位视线方向向量。本文采用的坐标约定为：相机坐标系中(X)轴指向图像右侧，(Y)轴指向图像下方，(Z)轴指向屏幕方向。该坐标约定与后续三维射线和平面求交过程保持一致。

三维标签构造的优势在于，它将“用户看向屏幕某一点”的监督信号转换为方向向量学习问题，而不是仅学习某一设备分辨率下的二维像素位置。这样可以将模型学习、屏幕几何和用户校准拆分为相互衔接的模块，有利于系统分析和误差定位。

## 4.4 GazeNetV2模型结构设计

### 4.4.1 模型设计思路

已有外观式视线估计研究表明，眼区图像、全脸上下文和头姿变化均会影响视线估计性能[3,4,6-8]。在此基础上，GazeNetV2采用左右眼图像和头部姿态向量作为输入，通过共享卷积神经网络提取双眼外观特征，并在融合层中结合头姿信息，最终回归三维视线方向单位向量。

模型设计遵循三个原则。第一，采用双眼输入而非单眼输入，使模型能够同时利用左右眼外观变化，提高对局部遮挡、单眼图像噪声和眼区检测误差的鲁棒性。第二，左右眼共享卷积骨干网络，使两只眼睛使用相同特征提取器，减少模型参数量并增强双眼特征的一致性。第三，将头部姿态作为辅助输入与双眼视觉特征融合，使模型能够学习眼部外观与头部姿态之间的关系。

【图4-4占位：GazeNetV2模型结构图。建议绘制为左右眼输入、共享CNN、单眼256维特征、头姿向量、515维融合特征、全连接回归层和L2归一化输出。】

图4-4 GazeNetV2模型结构

### 4.4.2 输入与输出定义

GazeNetV2的输入包括左眼图像、右眼图像和头姿向量。设左眼图像为(\mathbf{I}_L)，右眼图像为(\mathbf{I}_R)，头姿向量为(\mathbf{h})，则：

[
\mathbf{I}_L,\mathbf{I}_R \in \mathbb{R}^{3\times128\times128}
]

（4-9）

[
\mathbf{h}=
\begin{bmatrix}
yaw & pitch & roll
\end{bmatrix}^{T}
]

（4-10）

模型输出为三维视线方向单位向量：

[
\hat{\mathbf{g}}=
\begin{bmatrix}
\hat{g}_x & \hat{g}_y & \hat{g}_z
\end{bmatrix}^{T}
]

（4-11）

并满足：

[
|\hat{\mathbf{g}}|_2=1
]

（4-12）

其中，(\hat{g}_x)、(\hat{g}_y)和(\hat{g}_z)分别表示预测视线方向在相机坐标系三个方向上的分量。

### 4.4.3 共享卷积特征提取

GazeNetV2使用同一个卷积特征提取器分别处理左眼和右眼图像。卷积骨干由四组卷积模块组成，每组包含卷积、批归一化、ReLU激活和最大池化操作，通道数依次为32、64、128和256。经过卷积特征提取后，模型通过自适应平均池化将每只眼睛编码为256维特征向量。

设共享卷积特征提取器为(\phi(\cdot))，则左右眼特征可表示为：

[
\mathbf{z}_L=\phi(\mathbf{I}_L)
]

（4-13）

[
\mathbf{z}_R=\phi(\mathbf{I}_R)
]

（4-14）

其中：

[
\mathbf{z}_L,\mathbf{z}_R\in\mathbb{R}^{256}
]

（4-15）

共享卷积结构能够降低模型规模，并避免左右眼分支学习完全独立的特征空间。对于样本数量有限的自建数据集而言，参数共享有助于减轻过拟合，同时保留双眼输入带来的信息增益。

### 4.4.4 特征融合与三维回归

在得到左右眼特征后，模型将左眼特征、右眼特征和头姿向量进行拼接，得到融合特征：

[
\mathbf{z}=
\begin{bmatrix}
\mathbf{z}_L\
\mathbf{z}_R\
\mathbf{h}
\end{bmatrix}
\in\mathbb{R}^{515}
]

（4-16）

融合特征随后输入全连接回归头。回归头由线性层、ReLU激活、Dropout和输出线性层组成，将515维融合特征映射为3维未归一化视线向量：

[
\tilde{\mathbf{g}}=\psi(\mathbf{z})
]

（4-17）

其中，(\psi(\cdot))表示全连接回归头。最终输出通过L2归一化得到单位方向向量：

[
\hat{\mathbf{g}}=\frac{\tilde{\mathbf{g}}}{|\tilde{\mathbf{g}}|_2}
]

（4-18）

| 左眼共享CNN | (3\times128\times128) | 256维特征   | 与右眼分支共享权重      |

## 4.5 损失函数与训练策略

### 4.5.1 角度损失函数

由于GazeNetV2输出的是三维单位方向向量，训练目标应直接度量预测方向与真实方向之间的夹角。因此，本文采用角度损失作为主要训练目标。

设第(i)个样本的预测视线方向为(\hat{\mathbf{g}}_i)，真实视线方向为(\mathbf{g}_i)，二者均为单位向量，则角度误差为：

[
\theta_i=
\arccos
\left(
\operatorname{clamp}
\left(
\hat{\mathbf{g}}_i\cdot\mathbf{g}_i,,
-1+\varepsilon,,
1-\varepsilon
\right)
\right)
]

（4-19）

其中，(\cdot)表示向量点积，(\varepsilon)为防止数值误差导致反余弦函数输入越界的小常数。对一个批次中的(N)个样本取平均，得到角度损失：

[
\mathcal{L}_{angle}
===================

\frac{1}{N}\sum_{i=1}^{N}\theta_i
]

（4-20）

角度损失直接优化方向夹角，符合三维视线估计的评价目标。相比于直接对三个向量分量计算均方误差，角度损失更关注视线方向本身，并且与后续角度误差评估指标保持一致。

### 4.5.4 模型选择

在系统开发过程中，本文先完成了单眼输入基线模型，用于验证数据预处理、训练、推理和评估链路是否可行。随后，模型结构升级为GazeNetV2，引入双眼共享卷积特征提取和头姿融合机制。与单眼基线相比，GazeNetV2能够同时利用左右眼外观信息，且输出三维视线方向，能够与后续屏幕几何映射流程更好衔接。

近年来也有端到端帧到视线估计方法尝试直接从完整摄像头帧预测视线信息[18]，但本文更关注普通桌面摄像头系统中的轻量部署和可解释几何映射，因此最终选择GazeNetV2作为深度学习主模型。主要原因如下。第一，双眼输入比单眼输入包含更完整的眼部外观信息。第二，三维方向输出比直接二维屏幕坐标输出更具有几何可解释性。第三，轻量化结构便于导出为ONNX模型并部署到普通CPU环境中。第四，该模型能够作为后续校准、几何映射和跨用户误差分析的统一基础。

# 第五章 注视点映射、校准与交互实现

## 5.1 本章概述

前两章分别给出了 Look2Act 系统的总体架构和 GazeNetV2 深度视线估计模型。本章进一步说明实时追踪系统中的关键实现过程，包括人脸与眼区检测、Classic 传统视觉路线、Deep 深度学习路线、三维视线到屏幕点的几何映射、多点用户校准、注视点平滑、全屏验证和注视交互实现。

在实时系统中，模型输出或眼部特征并不能直接作为最终屏幕注视点。普通摄像头没有精确的硬件标定，摄像头位置、屏幕尺寸、用户坐姿、眼部结构和光照条件都会影响估计结果。因此，Look2Act 采用“原始估计—屏幕映射—用户校准—时序平滑—交互输出”的处理流程。该流程将视线估计任务拆分为多个可分析、可调试的模块，使系统不仅能够完成离线模型评估，也能够进入真实桌面交互场景进行验证。

本章重点围绕以下问题展开：第一，如何从实时摄像头帧中稳定提取人脸、眼区和头姿信息；第二，Classic 与 Deep 两种模式如何分别生成原始注视结果；第三，Deep 模式中的三维视线方向如何映射到屏幕坐标；第四，系统如何通过 25 点校准修正个体和设备偏差；第五，系统如何通过平滑与交互流程提升实际使用体验。

### 5.2.1 人脸关键点检测

系统使用人脸关键点检测方法获取面部轮廓、眼部区域和用于头姿估计的关键点，相关人脸网格与面部行为分析工具已被广泛用于实时 landmark、head pose 和 gaze 相关任务[12,13]。对于每一帧图像，检测模块输出以下信息：

1. 是否检测到有效人脸；
2. 左右眼区域裁剪图；
3. 左右眼 ROI 在原始摄像头画面中的位置；
4. 用于 PnP 头姿估计的二维关键点；
5. 眼区检测质量和调试信息。

当检测不到人脸或关键点质量不足时，系统不会直接输出新的注视点，而是进入容错逻辑。对于短时间检测失败的情况，系统可沿用上一帧有效注视结果；对于连续检测失败的情况，系统将当前帧标记为无效，并在界面上提示用户调整摄像头、光照或坐姿。该设计能够避免由于一两帧检测失败导致注视光标突然消失或剧烈跳变。

### 5.2.2 眼区图像裁剪

左右眼图像是 Classic 模式和 Deep 模式的共同输入。系统根据眼部关键点确定眼区边界，并从原始摄像头画面中裁剪左右眼 ROI。对于 Deep 模式，眼区图像需要进一步调整为模型要求的输入格式，包括尺寸统一、颜色通道转换、张量维度调整和归一化。对于 Classic 模式，眼区 ROI 则直接进入传统图像处理流程。

设原始摄像头帧为 (\mathbf{F})，左眼和右眼 ROI 分别为 (\Omega_L) 和 (\Omega_R)，则眼区图像可表示为：

[
\mathbf{E}_L=\mathbf{F}(\Omega_L)
]

（5-1）

[
\mathbf{E}_R=\mathbf{F}(\Omega_R)
]

（5-2）

其中，(\mathbf{E}_L) 和 (\mathbf{E}_R) 分别表示裁剪后的左眼图像和右眼图像。Deep 模式中，二者被缩放和归一化为 (3\times128\times128) 的模型输入张量。

### 5.2.3 头部姿态估计

用户头部姿态会影响眼部外观和视线方向，因此系统在实时处理中保留头姿估计模块。头姿估计采用 PnP 方法，通过若干个三维人脸模型点与二维图像关键点之间的对应关系求解头部旋转和平移。

设第 (i) 个三维人脸模型点为 (\mathbf{X}_i)，其在图像平面上的二维投影为 (\mathbf{u}_i)，相机内参矩阵为 (K)，头部旋转矩阵和平移向量分别为 (R) 和 (t)，则投影关系可表示为：

[
s_i
\begin{bmatrix}
u_i\
v_i\
1
\end{bmatrix}
=============

K
\left(
R\mathbf{X}_i+t
\right)
]

（5-3）

其中，(s_i) 为尺度因子。系统通过求解该方程得到头部姿态，并进一步转换为 yaw、pitch、roll 三个欧拉角。头姿信息可用于模型输入、几何分析、运行状态监测和误差分析。

需要说明的是，GazeNetV2 模型结构支持头姿输入，训练阶段也保留了头姿特征通道；在最终实时部署中，Deep 模式提供实时头姿输入和零姿态输入两种策略。为保证当前三维标签约定、模型输出空间和实时屏幕映射契约的一致性，最终演示配置采用零姿态输入，同时保留实时头姿估计结果用于状态监测和后续扩展。该设计避免了因离线标签坐标约定与实时 PnP 姿态约定不一致而引入额外变换误差。

## 5.3 Classic 传统视觉路线实现

### 5.3.1 瞳孔或暗色区域特征提取

眼区图像中，瞳孔和虹膜区域通常比眼白区域更暗，因此可以通过灰度图像和阈值分割提取暗色区域。Classic 模式首先将眼区 ROI 转换为灰度图像，并进行高斯模糊以降低噪声。随后采用反向阈值分割得到暗色区域掩膜，并通过形态学开运算和闭运算去除小噪声、填补区域空洞。

设眼区灰度图像为 (I(x,y))，阈值为 (\tau)，则暗色区域掩膜可表示为：

[
M(x,y)=
\begin{cases}
1, & I(x,y)<\tau\
0, & I(x,y)\geq \tau
\end{cases}
]

（5-4）

得到掩膜后，系统选择面积较大的连通区域作为瞳孔或暗色区域候选，并通过图像矩计算质心。设候选区域为 (\Omega)，则质心坐标为：

[
c_x=\frac{\sum_{(x,y)\in\Omega}x}{|\Omega|}
]

（5-5）

[
c_y=\frac{\sum_{(x,y)\in\Omega}y}{|\Omega|}
]

（5-6）

当轮廓检测失败或候选区域不稳定时，系统使用暗像素加权质心作为备用估计方式。设暗度权重为 (w(x,y)=255-I(x,y))，则加权质心为：

[
c_x=\frac{\sum xw(x,y)}{\sum w(x,y)}
]

（5-7）

[
c_y=\frac{\sum yw(x,y)}{\sum w(x,y)}
]

（5-8）

该备用策略能够在瞳孔轮廓不完整或眼区局部反光时提供连续输出。

### 5.3.2 左右眼特征融合

单眼特征容易受到眨眼、局部遮挡和光照变化影响，因此系统对左右眼特征进行融合。首先，系统将 ROI 内的瞳孔质心坐标还原到原始摄像头画面坐标；随后，对可用的左右眼点取平均，得到融合后的相机平面特征点。

设左眼和右眼在摄像头画面中的绝对特征点分别为 (\mathbf{p}_L=(x_L,y_L)^T) 和 (\mathbf{p}_R=(x_R,y_R)^T)，有效眼集合为 (\mathcal{E})，则融合特征点为：

[
\mathbf{p}*{eye}=
\frac{1}{|\mathcal{E}|}
\sum*{\mathbf{p}_i\in\mathcal{E}}
\mathbf{p}_i
]

（5-9）

随后，系统根据摄像头画面宽度 (W_c) 和高度 (H_c) 将其归一化：

[
\mathbf{r}*{classic}=
\begin{bmatrix}
x*{eye}/W_c\
y_{eye}/H_c
\end{bmatrix}
]

（5-10）

其中，(\mathbf{r}_{classic}) 为 Classic 模式输出的原始归一化特征点。该点本身不是屏幕注视点，需要经过用户校准映射后才能用于屏幕交互。

### 5.3.3 Classic 模式特点

Classic 模式具有结构轻量、计算开销小和处理过程可解释等特点。该模式能够直观展示传统图像处理方法如何从眼区图像中提取视线相关特征，并通过校准映射形成屏幕注视点。其局限性也较明显：当光照变化、眼镜反光、瞳孔边界不清或用户眼部外观差异较大时，暗色区域质心可能与真实视线变化不完全一致。

因此，Classic 模式在本文中定位为传统视觉实现路线和系统对照路线。它与 Deep 模式共用同一套界面、校准、验证和交互流程，使系统能够在统一条件下展示传统视觉方法和深度学习方法的实际表现差异。

Deep 模式从实时摄像头帧中裁剪左右眼图像，并将其转换为模型输入张量。主要处理步骤包括：

2. 将 BGR 图像转换为 RGB 图像；
3. 将图像尺寸统一为 (128\times128)；

### 5.4.2 运行时几何契约

Deep 模式中的三维视线方向必须与屏幕几何映射使用相同的坐标约定。本文采用相机坐标系作为实时映射的统一坐标系，约定 (X) 轴指向图像右侧，(Y) 轴指向图像下方，(Z) 轴指向屏幕方向。模型输出的三维视线方向经过归一化后作为相机空间中的射线方向。

设模型输出为 (\hat{\mathbf{g}})，则实时映射中使用的射线方向为：

[
\mathbf{d}=\frac{\hat{\mathbf{g}}}{|\hat{\mathbf{g}}|_2}
]

（5-12）

在当前部署配置中，Deep 模式射线原点取相机近似原点：

[
\mathbf{o}=
\begin{bmatrix}
0\
0\
0
\end{bmatrix}
]

（5-13）

于是，三维视线射线可以表示为：

[
\mathbf{P}(\lambda)=\mathbf{o}+\lambda\mathbf{d}
]

（5-14）

其中，(\lambda) 为射线参数。当 (\lambda>0) 时，射线方向指向屏幕前方；当 (\lambda\leq0) 时，交点在射线反方向，不作为有效屏幕注视点。

该配置的核心目的在于保证训练标签、模型输出和实时屏幕映射之间的坐标约定一致。对于普通摄像头系统而言，如果离线标签构造与实时头姿变换之间存在坐标约定差异，错误的坐标变换可能导致屏幕点拓扑折叠或大范围偏移。因此，实时系统在最终配置中采用更稳定的一致性契约，并将更复杂的头姿补偿作为后续优化方向和第六章中的误差分析对象。

## 5.5 三维视线到屏幕坐标的几何映射

Deep 模式输出三维视线方向后，系统需要将其转换为屏幕二维坐标。Look2Act 采用射线与屏幕平面求交的方法完成该过程。

### 5.5.1 屏幕平面定义

在相机坐标系中，屏幕可以近似为一个三维平面。设屏幕平面上一点为 (\mathbf{p}_0)，屏幕平面法向量为 (\mathbf{n})，则屏幕平面满足：

[
\mathbf{n}\cdot(\mathbf{p}-\mathbf{p}_0)=0
]

（5-15）

其中，(\mathbf{p}) 为平面上任意一点。系统根据屏幕物理尺寸、屏幕分辨率和相机到屏幕的近似距离构造该平面。屏幕局部坐标系包含水平方向单位向量 (\mathbf{e}_x) 和竖直方向单位向量 (\mathbf{e}_y)，分别对应屏幕像素坐标中的横向和纵向方向。

【图5-5占位：三维视线射线与屏幕平面求交示意图。图中应标注相机坐标系、射线原点、视线方向、屏幕平面、交点、屏幕局部坐标和像素坐标。】

图5-5 三维视线到屏幕坐标几何映射

### 5.5.2 射线和平面求交

将式（5-14）代入屏幕平面方程，可求得射线参数：

[
\lambda=
\frac{\mathbf{n}\cdot(\mathbf{p}_0-\mathbf{o})}
{\mathbf{n}\cdot\mathbf{d}}
]

（5-16）

当 (\mathbf{n}\cdot\mathbf{d}) 接近 0 时，射线与屏幕平面近似平行，无法得到稳定交点。当 (\lambda<0) 时，交点位于射线反方向，也不作为有效注视点。若满足有效条件，交点为：

[
\mathbf{p}=\mathbf{o}+\lambda\mathbf{d}
]

（5-17）

该交点位于三维相机坐标系中，还需要转换为屏幕局部坐标和像素坐标。

### 5.5.3 三维交点到屏幕像素坐标

设屏幕左上角对应三维点为 (\mathbf{p}_{tl})，屏幕水平方向单位向量为 (\mathbf{e}_x)，竖直方向单位向量为 (\mathbf{e}_y)。交点 (\mathbf{p}) 在屏幕平面上的物理坐标为：

[
x_{mm}=(\mathbf{p}-\mathbf{p}_{tl})\cdot\mathbf{e}_x
]

（5-18）

[
y_{mm}=(\mathbf{p}-\mathbf{p}_{tl})\cdot\mathbf{e}_y
]

（5-19）

设屏幕物理宽度和高度分别为 (W_{mm}) 和 (H_{mm})，屏幕像素宽度和高度分别为 (W_{px}) 和 (H_{px})，则屏幕像素坐标为：

[
x_{px}=\frac{x_{mm}}{W_{mm}}W_{px}
]

（5-20）

[
y_{px}=\frac{y_{mm}}{H_{mm}}H_{px}
]

（5-21）

其中，屏幕像素坐标原点位于左上角，(x) 轴向右，(y) 轴向下。正常追踪模式下，系统会将最终输出限制在屏幕范围内；校准采样阶段则不对原始点进行边界截断，以避免校准拟合受到截断点污染。

## 5.6 用户校准模块实现

### 5.6.1 校准的必要性

无论 Classic 模式还是 Deep 模式，原始输出都难以直接达到稳定的屏幕注视点效果。Classic 模式的原始输出是归一化眼部特征点；Deep 模式的原始输出经过几何映射后得到屏幕原始点。二者都会受到用户眼部结构、摄像头位置、屏幕参数、坐姿和环境光照的影响。因此，系统需要通过用户校准建立原始输出与真实屏幕目标点之间的映射关系。已有校准和少样本个性化研究也表明，低负担校准是 gaze-based HCI 系统落地的重要环节[9,10]。

用户校准的基本思想是：让用户依次注视屏幕上的若干个目标点，系统同时记录算法输出的原始点 (\mathbf{p}_i^{raw}) 和对应目标点 (\mathbf{p}_i^{target})，随后拟合一个映射函数 (h(\cdot))，使校准后的点尽可能接近目标点。

校准目标可写为：

[
h^*=
\arg\min_h
\sum_{i=1}^{N}
\left|
h(\mathbf{p}_i^{raw})
---------------------

\mathbf{p}_i^{target}
\right|_2^2
]

（5-22）

其中，(N) 为校准样本数量。

7. 保存校准参数；
8. 进入全屏验证阶段。

### 5.6.3 仿射映射

仿射映射适合描述平移、缩放、旋转和剪切等线性变换。设原始点为 (\mathbf{p}^{raw}=(x,y)^T)，校准后的屏幕点为 (\mathbf{p}'=(x',y')^T)，则仿射映射为：

[
\begin{bmatrix}
x'\
y'
\end{bmatrix}
=============

A
\begin{bmatrix}
x\
y\
1
\end{bmatrix}
]

（5-23）

其中，(A\in\mathbb{R}^{2\times3}) 为待求映射矩阵。给定校准样本后，可通过最小二乘方法求解 (A)。

仿射映射参数较少，稳定性较好，适合少点校准场景。在第六章实验分析中，本文将进一步比较不同校准点数和映射方式对误差的影响。

### 5.6.4 二阶多项式映射

当校准点数量较多且覆盖范围较完整时，可以使用二阶多项式映射表达更复杂的非线性偏差。设原始点为 ((x,y))，二阶多项式特征为：

[
\boldsymbol{\phi}(x,y)=
\begin{bmatrix}
x\
y\
xy\
x^2\
y^2\
1
\end{bmatrix}
]

（5-24）

则校准映射为：

[
\begin{bmatrix}
x'\
y'
\end{bmatrix}
=============

W\boldsymbol{\phi}(x,y)
]

（5-25）

其中，(W\in\mathbb{R}^{2\times6}) 为待求参数矩阵。二阶多项式映射能够表达部分非线性偏差，但参数更多，对校准点覆盖和采样质量更敏感。为提高数值稳定性，系统在拟合多项式映射前对原始点进行归一化处理，并在应用映射后转换回屏幕像素坐标。

最终系统在 25 点校准配置下使用多项式映射，以利用较完整的校准点覆盖；少点校准时则更适合使用参数较少的仿射映射。

## 5.7 注视点平滑与稳定处理

### 5.7.1 平滑处理的必要性

普通 RGB 摄像头视线追踪结果存在明显帧间噪声。噪声来源包括摄像头图像噪声、关键点检测误差、眼区裁剪抖动、模型推理误差、头部微小运动和校准映射放大效应。如果直接将逐帧原始注视点显示为光标，用户会感受到明显抖动，影响全屏验证和注视交互体验。

因此，Look2Act 在输出层加入平滑模块。平滑模块的目标不是提高离线标签精度，而是改善实时交互中的视觉稳定性。平滑强度需要在抖动抑制和响应延迟之间取得平衡。若平滑过强，注视光标会滞后于用户真实视线；若平滑过弱，光标会抖动明显，影响停留触发和目标选择。

【图5-8占位：注视点平滑前后对比图。建议使用同一段追踪轨迹，展示 raw point 与 smoothed point 的轨迹差异。】

图5-8 注视点平滑前后对比

### 5.7.2 指数滑动平均

Deep 模式最终部署中采用指数滑动平均作为主要平滑方法。设当前校准后的注视点为 (\mathbf{x}*t)，上一帧平滑结果为 (\mathbf{s}*{t-1})，当前平滑输出为 (\mathbf{s}_t)，则指数滑动平均为：

[
\mathbf{s}_t=\alpha\mathbf{x}*t+(1-\alpha)\mathbf{s}*{t-1}
]

（5-27）

其中，(\alpha\in(0,1]) 为平滑系数。当 (\alpha) 较大时，系统响应更快但抖动更明显；当 (\alpha) 较小时，输出更稳定但延迟更高。

指数滑动平均的优点是实现简单、计算量小、适合实时系统部署；交互系统中的滤波方法通常需要在 jitter 和 lag 之间取得平衡[15]。其缺点是对速度变化没有显式建模，因此在用户快速转移视线时可能产生一定滞后。

### 5.7.3 屏幕空间稳定器

Classic 模式在交互输出层采用屏幕空间稳定策略，对校准后的屏幕点进行连续性处理。该策略结合运动状态估计和短期历史信息，降低传统视觉特征点在光照变化和眼区噪声下产生的抖动。与 Deep 模式中的三维方向平滑不同，Classic 模式的稳定处理主要作用于校准后的二维屏幕坐标。

## 5.8 全屏验证与注视交互实现

### 5.8.1 全屏验证流程

视线追踪系统不能只依赖离线误差指标判断是否可用，已有应用评价和 webcam gaze 系统研究均强调校准、交互反馈和系统级指标的重要性[11,14]。用户完成校准后，还需要在真实屏幕环境中确认注视点是否能够在主要区域内稳定移动。因此，Look2Act 在进入交互阶段前设置了全屏验证流程。

全屏验证流程要求用户先完成校准，再进入验证页面。验证页面通常以全屏方式显示目标点、注视光标或参考区域，用户通过观察光标与目标点之间的关系判断当前校准质量。如果验证结果不理想，用户可以返回校准阶段重新采样；如果验证通过，系统进入交互阶段。

【图5-9占位：全屏验证界面截图。建议使用最终软件真实截图，标注验证目标点、注视光标、验证进度和返回提示。】

图5-9 全屏验证界面

全屏验证的作用包括三个方面。第一，它可以在正式交互前发现校准失败、摄像头状态异常或用户姿态变化。第二，它为用户提供直观反馈，使用户能够理解系统当前追踪效果。第三，它将“模型输出有效”与“交互可用”区分开来，避免系统在校准质量不足时直接进入交互任务。

### 5.8.2 注视光标显示

校准和平滑后的注视点用于驱动屏幕上的注视光标。注视光标的显示应满足两个要求：一是位置能够反映系统当前估计的注视点；二是不应过度遮挡用户正在观察的目标。因此，注视光标通常采用较小的圆形或带透明度的覆盖层显示。

设最终输出注视点为：

[
\mathbf{p}^{final}=
\begin{bmatrix}
x^{final}\
y^{final}
\end{bmatrix}
]

（5-28）

系统将该坐标传递给全屏覆盖层，并在对应位置绘制注视光标。若当前帧无效或长时间未检测到人脸，系统可以隐藏光标或保持上一帧有效位置，并在状态栏中提示检测异常。

### 5.8.3 停留触发交互

注视交互中最常见的问题是“用户只是看了一眼目标，系统却误判为点击”。为降低误触发风险，Look2Act 采用停留触发方式实现基础交互。系统持续检测注视点是否位于某个目标区域内，当注视点在同一区域内停留时间超过设定阈值时，触发该目标对应操作。

设目标区域为 (\mathcal{R})，注视点为 (\mathbf{p}_t)，指示函数为：

[
\delta_t=
\begin{cases}
1, & \mathbf{p}_t\in\mathcal{R}\
0, & \mathbf{p}_t\notin\mathcal{R}
\end{cases}
]

（5-29）

若连续满足 (\delta_t=1) 的时间达到阈值 (T_d)，则触发交互事件：

[
Event=
\begin{cases}
1, & \sum_{k=t-m+1}^{t}\Delta t_k \geq T_d\
0, & otherwise
\end{cases}
]

（5-30）

其中，(\Delta t_k) 为相邻帧间隔，(m) 为连续位于目标区域内的帧数。停留触发能够降低瞬时误差造成的误点击，同时适合大目标选择、菜单启动和简单桌面交互任务。

# 第六章 实验结果与系统测试

## 6.1 本章概述

前几章分别介绍了 Look2Act 系统的总体设计、数据集构建、GazeNetV2 深度视线估计模型、注视点映射、用户校准和平滑交互实现。本章在此基础上对系统进行实验验证与性能分析，重点评价深度学习模型的离线精度、跨用户泛化能力、校准映射效果、系统实时性和功能完整性。

对于普通 RGB 摄像头视线追踪系统而言，仅报告模型角度误差不足以说明系统是否可用于交互，应用场景还需要结合校准状态、使用距离、用户条件和交互任务进行评价[11]。视线追踪从摄像头输入到屏幕交互输出之间包含多个环节，包括眼区检测、三维视线估计、屏幕几何映射、用户校准、时序平滑和交互触发。任一环节的误差都可能影响最终屏幕注视点。因此，本文采用多层次实验方式进行评价：第一，通过固定训练集、验证集和测试集划分评价 GazeNetV2 模型的基本性能；第二，通过留一用户交叉验证评价模型在新用户上的泛化能力；第三，通过校准对比实验分析不同校准策略对屏幕误差的影响；第四，通过系统运行测试验证软件功能、实时性和部署可用性；第五，通过 Classic 与 Deep 两种模式的实际表现分析系统双模式设计的工程意义。

本章实验指标主要包括角度误差、屏幕像素误差、跨用户误差、校准后误差、帧率、模块耗时和功能通过情况。其中，角度误差用于评价三维视线方向回归能力，像素误差用于评价屏幕注视点估计效果，系统测试指标用于评价软件在真实运行环境中的可用性。

### 6.2.2 角度误差

角度误差用于评价预测三维视线方向与真实三维视线方向之间的夹角。设模型预测视线方向为 (\hat{\mathbf{g}})，真实视线方向为 (\mathbf{g})，二者均为单位向量，则角度误差定义为：

[
\theta=
\arccos
\left(
\operatorname{clamp}
\left(
\hat{\mathbf{g}}\cdot\mathbf{g},-1,1
\right)
\right)
]

（6-1）

其中，(\theta) 的单位为弧度，实验统计时转换为角度单位：

[
\theta_{deg}=\theta\cdot\frac{180}{\pi}
]

（6-2）

角度误差越小，说明模型预测的三维视线方向越接近真实方向。由于 GazeNetV2 输出三维单位向量，因此角度误差是评价深度学习主模型的核心指标。

### 6.2.3 屏幕像素误差

屏幕像素误差用于评价预测注视点与真实目标点之间的二维距离。设预测屏幕点为 (\hat{\mathbf{p}}=(\hat{x},\hat{y})^T)，真实目标点为 (\mathbf{p}=(x,y)^T)，则像素误差定义为：

[
e_{px}=
\left|
\hat{\mathbf{p}}-\mathbf{p}
\right|_2
=========

\sqrt{(\hat{x}-x)^2+(\hat{y}-y)^2}
]

（6-3）

屏幕像素误差反映了系统输出在屏幕交互层面的偏差。对于普通摄像头视线追踪系统而言，角度误差较小并不必然意味着屏幕像素误差较小，因为三维方向到二维屏幕点的转换还受到屏幕几何参数、相机位置、头姿估计和校准映射等因素影响。

### 6.2.4 实时性与稳定性指标

系统实时性主要通过帧率和模块耗时评价。设系统在时间窗口 (\Delta T) 内处理的视频帧数为 (N_f)，则平均帧率为：

[
FPS=\frac{N_f}{\Delta T}
]

（6-4）

模块耗时用于分析系统瓶颈，主要包括人脸检测耗时、头姿估计耗时、模型推理耗时、几何映射耗时、校准映射耗时和平滑处理耗时。系统稳定性可通过注视点抖动、无效帧比例和连续运行情况进行评价。若一段稳定注视序列中第 (t) 帧输出为 (\mathbf{p}_t)，序列均值为 (\bar{\mathbf{p}})，则抖动均方根可表示为：

[
J_{rms}=
\sqrt{
\frac{1}{T}
\sum_{t=1}^{T}
\left|
\mathbf{p}_t-\bar{\mathbf{p}}
\right|_2^2
}
]

（6-5）

其中，(J_{rms}) 越小，说明注视点在稳定注视状态下越平稳。由于本课题重点是系统构建与可运行验证，实时性和稳定性测试主要用于说明软件能否支持连续演示和基础注视交互。

### 6.3.2 固定划分结果分析

固定测试集结果表明，GazeNetV2 已经能够完成可用的三维视线方向回归。双眼共享卷积结构使模型能够同时利用左右眼信息，头姿输入通道为模型提供了辅助几何上下文，L2归一化输出保证预测结果为三维单位方向向量。

然而，平均屏幕像素误差仍明显高于角度误差所呈现的方向误差水平。这说明普通摄像头视线追踪系统的系统级误差并不完全来自模型回归本身。三维方向到二维屏幕点的映射涉及相机与屏幕之间的几何关系，而普通笔记本摄像头通常缺少精确内外参标定。屏幕物理尺寸、摄像头安装位置、用户眼睛相对摄像头的位置、头部运动和坐姿差异都会使屏幕映射误差被放大。因此，用户校准和平滑处理对于最终交互效果具有重要作用。

固定划分测试的意义在于证明深度学习主模型具备基本方向估计能力，但它不能单独代表最终系统的交互可用性。为了进一步验证模型面对新用户时的表现，本文进行了跨用户留一评估。

## 6.4 跨用户泛化实验

### 6.4.1 留一用户交叉验证设计

在真实使用场景中，系统通常需要面对训练阶段未出现过的新用户。因此，仅使用随机样本划分不能充分评价模型泛化能力。为分析模型在新用户上的表现，本文采用留一用户交叉验证。实验时，每一轮选择1名用户作为测试用户，其余用户的数据用于训练和验证。该过程重复31轮，使每名用户都作为一次独立测试用户。

4. 记录该用户的角度误差和像素误差；
5. 重复上述过程，直到31名用户均被测试；
6. 统计所有用户的平均误差、中位误差和长尾用户表现。

### 6.4.3 跨用户结果分析

留一用户实验的核心意义在于评价模型面对新用户时的可迁移能力。从结果看，GazeNetV2 已经具备较好的跨用户方向估计能力。对于普通RGB摄像头视线追踪系统而言，跨用户误差控制在较低角度范围内说明深度学习路线具有实际研究价值。

但跨用户结果也说明，仅依赖统一模型无法完全解决个体差异。眼睛形状、眼睑遮挡、虹膜颜色、眼镜反光、摄像头角度和用户习惯坐姿都会影响眼区外观，使某些用户成为困难样本。因此，后续系统仍需要通过用户校准、数据补充、个性化适配和更稳定的几何建模进一步降低屏幕误差。

从系统角度看，跨用户实验支持本文的设计判断：Look2Act 不能只依赖模型回归，而应将模型估计、屏幕几何、用户校准和平滑交互作为整体链路共同优化。

## 6.5 校准映射实验

### 6.5.1 校准实验目的

普通摄像头视线追踪系统中，屏幕像素误差往往包含明显的用户和设备偏差。即使模型能够较准确地估计三维视线方向，屏幕映射仍会受到摄像头位置、屏幕距离、坐姿和个体眼部结构影响。因此，用户校准是将模型输出转化为可交互屏幕坐标的重要步骤，快速校准和少样本个性化研究均表明，少量用户数据可以显著改善实际 gaze 系统表现[9,10]。

本文对不同校准点数量和映射方式进行了对比分析。校准实验的目的不是替代最终系统中的 25 点实时校准流程，而是分析少量校准点条件下不同映射策略的稳定性，为校准模块设计提供依据。实验比较了无校准、少点校准、仿射映射和多项式映射等方式对屏幕误差的影响。

### 6.5.2 校准策略对比

校准映射的基本目标是学习从原始注视点到目标屏幕点的映射函数。本文重点比较仿射映射和多项式映射。仿射映射参数较少，能够表达平移、缩放、旋转和剪切等线性变化；多项式映射表达能力更强，但在校准点数量不足或采样质量不稳定时可能出现过拟合。

少点校准对比结果见表6-4。

## 6.6 头姿与几何链路分析

### 6.6.1 头姿信息的作用

头部姿态会影响眼部外观和视线方向估计。用户在屏幕前自然使用时，很难保持头部完全静止。即使眼睛注视同一屏幕点，头部姿态变化也会导致眼区图像和视线方向发生变化。因此，在视线估计系统中引入头姿信息具有重要意义。

GazeNetV2 模型结构保留头姿输入通道，使模型能够在训练阶段学习眼部外观与头部姿态之间的关系。实时系统中也保留 PnP 头姿估计模块，用于状态监测、几何分析和后续扩展。为了分析头姿因素对系统误差的影响，本文对头姿相关配置进行了对比实验。

### 6.6.3 几何链路与实时配置讨论

虽然头姿信息对视线估计具有重要作用，但普通摄像头条件下的头姿估计也可能带来新的误差来源。PnP 头姿估计依赖人脸关键点、相机内参近似和三维人脸模型点设定。当关键点检测抖动、相机参数不精确或坐标约定不一致时，直接将头姿变换用于实时屏幕映射可能造成额外误差。

因此，最终系统在 Deep 模式实时部署中采用更稳定的相机空间几何契约：模型输出作为相机坐标系下的三维视线方向，射线原点取相机近似原点，并使用与当前标签构造一致的姿态输入方式。这一配置的目标是优先保证实时映射拓扑稳定，避免因坐标空间不一致导致屏幕点大范围折叠或偏移。

上述结果表明，头姿信息具有明确价值，但如何将离线头姿建模、实时PnP估计和屏幕几何映射严格统一，仍是普通摄像头视线追踪系统中的关键问题。本文系统保留头姿估计模块，并将更鲁棒的头姿补偿作为后续优化方向。

## 6.7 Classic 与 Deep 双模式系统表现

### 6.7.1 双模式评价目的

Look2Act 系统实现了 Classic 与 Deep 两种运行模式。Classic 模式基于传统图像处理提取眼部特征，Deep 模式基于 GazeNetV2 回归三维视线方向。二者分别对应基于特征的方法和基于外观的深度学习方法两类主要技术路线[2-8]。二者共用摄像头输入、用户界面、校准流程、验证流程和交互页面，但视线估计后端不同。

双模式评价的目的不是简单判定某一种方法完全优于另一种方法，而是分析两条路线在普通摄像头桌面交互场景下的不同特点。Classic 模式更轻量，处理过程直观，校准后在大目标交互场景中具有较好的连续性；Deep 模式体现本文模型训练和三维视线估计研究成果，能够通过固定划分和跨用户实验进行定量评价，但实时屏幕映射效果更依赖几何契约、校准质量和运行环境。

### 6.7.3 模式差异分析

Classic 模式的优势在于链路短、计算量小、实时响应直接。其结果主要依赖眼区暗色区域检测和校准映射，因此在用户坐姿稳定、光照较好和目标较大的场景中表现较自然。其不足在于特征表达能力有限，当用户佩戴眼镜、眼区反光明显或瞳孔边界不清时，暗色区域质心可能无法准确反映视线变化。

Deep 模式的优势在于表达能力更强，能够从左右眼图像中学习更复杂的外观特征，并输出具有物理意义的三维方向向量。其不足在于实时系统需要严格保证训练标签、模型输出、头姿输入和屏幕几何之间的坐标约定一致。若几何契约不稳定，屏幕注视点可能出现系统性偏差。因此，Deep 模式的后续优化重点应放在数据覆盖、坐标约定、用户校准和长尾用户适配上。

## 6.11 误差来源分析

综合固定划分测试、跨用户实验、校准实验和系统测试结果，Look2Act 的误差来源主要包括以下几个方面。

第一，数据分布差异。不同用户的眼部外观、佩戴眼镜情况、虹膜颜色、眼睑遮挡和注视习惯存在差异，导致模型在部分用户上误差较大。跨用户留一实验中的长尾用户现象说明，模型泛化能力仍需要通过更多样本覆盖和个性化适配进一步提升。

第二，摄像头与屏幕几何误差。普通笔记本或外接摄像头的真实位置、视场角和内参并不完全已知，屏幕距离和物理尺寸也只能近似配置。三维视线方向到屏幕平面求交过程中，这些近似会放大为屏幕像素误差。

第三，头姿估计误差。PnP 头姿估计依赖人脸关键点质量、相机参数和简化三维人脸模型。当用户头部转动较大、光照不足或关键点抖动时，头姿估计误差会影响模型输入和几何映射。

第四，眼区裁剪和图像质量。眼区裁剪若包含较多背景、眼睑遮挡或反光区域，模型和传统视觉方法都会受到影响。Classic 模式对暗色区域质量更敏感，Deep 模式则更依赖训练数据是否覆盖类似眼区外观。

第五，校准采样质量。用户在校准过程中如果没有准确注视目标点，或者采样阶段存在检测失败和注视点抖动，校准映射会受到影响。映射函数复杂度过高也可能在少点条件下产生过拟合。

第六，时序平滑与交互延迟。平滑能够降低抖动，但会引入一定延迟。对于停留触发任务，适度平滑有利于稳定选择；对于快速视线转移，过强平滑可能导致光标滞后。

上述分析说明，普通摄像头视线追踪系统的性能瓶颈并不只在模型本身。一个可用系统需要同时处理视觉检测、模型估计、几何映射、用户校准、时序稳定和交互设计等多个问题。

## 6.12 本章小结

本章对 Look2Act 系统进行了实验验证和系统测试。首先，本文基于31名用户、16台设备和7395条有效样本的自建数据集，对 GazeNetV2 模型进行了固定划分测试。结果表明，模型在1390条测试样本上取得 2.8206° 的平均角度误差、1.98° 的中位角度误差和 314.5413 px 的平均屏幕像素误差，说明模型具备较好的三维视线方向回归能力。

其次，本文通过31名用户留一交叉验证分析模型跨用户泛化能力。实验结果显示，GazeNetV2 在留一用户评估中取得 2.4788° 的平均角度误差和 321.3820 px 的平均屏幕像素误差，其中23名用户角度误差不超过3°。该结果表明模型对多数新用户具有较好的泛化基础，但仍存在少数长尾用户误差较大的问题。

在校准实验中，9点仿射校准能够将平均像素误差从 314.5 px 降低到 221.2 px，而9点多项式映射出现误差升高，说明少点校准场景中稳定性比映射复杂度更重要。最终系统采用25点实时校准流程，用于覆盖更完整的屏幕区域并服务于真实交互阶段。头姿消融实验表明，头姿相关信息对屏幕误差具有重要影响，但在普通摄像头实时系统中，头姿估计、模型输出和屏幕几何之间的坐标约定必须严格统一。

最后，本章对 Classic 与 Deep 双模式、软件功能、实时性和注视交互进行了测试与分析。Classic 模式体现传统视觉方法在实时交互中的轻量性和可解释性，Deep 模式体现本文深度学习模型训练和三维视线估计的研究成果。整体来看，Look2Act 已经形成从数据采集、模型训练、实时追踪、用户校准到注视交互的完整系统闭环，适合用于注视点可视化、大目标选择、停留触发和普通摄像头视线交互原型验证。

# 第七章 总结与展望

## 7.1 研究工作总结

本文围绕“实时视线追踪技术研究与实现”这一课题，设计并实现了一套基于普通 RGB 摄像头的实时视线追踪与注视交互系统 Look2Act。系统面向普通 Windows 桌面计算环境，不依赖红外眼动仪、专用光源和专用追踪硬件，通过摄像头图像完成用户眼区检测、视线估计、屏幕映射、用户校准、时序平滑和交互输出。本文的研究重点不仅包括深度学习视线估计模型的训练与评估，也包括将模型结果转化为可运行软件系统所需的几何映射、校准策略、实时处理和交互流程。

首先，本文完成了系统总体架构设计。Look2Act 由数据采集系统和 Tracker 追踪系统两部分组成。数据采集系统用于采集用户注视屏幕目标点时的眼区图像、头姿信息、屏幕标签和设备信息；Tracker 系统用于完成模型训练、实时推理、用户校准、全屏验证和注视交互。系统整体形成了“数据采集—数据预处理—模型训练—实时追踪—用户校准—验证交互”的完整链路，满足工程设计类软件课题对系统设计、模块实现、调试测试和软件成果的要求。

其次，本文构建了面向真实桌面场景的自建视线数据集。数据采集采用 5×5 屏幕目标点方案，覆盖屏幕中心、边缘和角落区域。最终数据集包含 31 名用户、16 台设备和 7395 条有效样本。预处理阶段完成了有效样本筛选、左右眼图像提取、屏幕坐标归一化和三维视线方向标签构造。考虑到数据中包含真实用户眼部图像、设备信息和采集会话信息，本文数据集仅用于本课题训练、评估和系统验证，不作为公开数据集发布。

再次，本文设计并训练了 GazeNetV2 深度视线估计模型。该模型采用左右眼共享卷积特征提取结构，以左右眼 128×128 图像和头姿向量为输入，融合双眼外观特征和姿态信息后回归三维视线方向单位向量。训练阶段采用角度损失优化预测方向与真实方向之间的夹角，部署阶段将训练完成的模型导出为 ONNX 格式，用于本地实时推理。该模型是本文深度学习路线的核心，为后续三维视线到屏幕注视点的几何映射提供了基础。

第四，本文实现了 Classic 与 Deep 双模式视线追踪框架。Classic 模式基于传统计算机视觉方法，通过眼区灰度化、阈值分割、形态学处理和质心计算提取眼部暗色区域特征，并通过用户校准映射到屏幕坐标。Deep 模式基于 GazeNetV2 模型输出三维视线方向，并结合屏幕平面求交、校准映射和平滑处理得到最终注视点。两种模式共用摄像头输入、界面流程、校准模块、验证模块和交互模块，形成了传统视觉路线与深度学习路线并行的系统结构。

第五，本文完成了屏幕几何映射、用户校准和平滑交互模块。对于 Deep 模式，系统通过三维射线与屏幕平面求交，将模型输出的三维视线方向转换为原始屏幕坐标；对于 Classic 模式，系统将眼部特征点作为原始输入，通过校准映射得到屏幕点。最终系统采用 5×5 共 25 点校准流程，以修正个体差异、摄像头位置差异和屏幕几何近似误差。系统还引入指数滑动平均和屏幕空间稳定处理，降低帧间抖动，提高注视光标和停留触发的稳定性。

最后，本文实现了可运行的软件系统和交互演示。Look2Act 提供启动模式选择、摄像头预览、视线校准、实时追踪、全屏验证、交互启动器和五子棋演示等功能，并支持 Windows 本地可执行程序运行。系统能够完成从摄像头输入到注视点输出、从注视点估计到注视交互的完整流程，形成了本课题的软件成果。

## 7.2 主要实验结论

本文通过固定划分测试、留一用户交叉验证、校准对比实验、头姿消融分析、双模式系统表现分析和系统功能测试，对 Look2Act 的模型性能和系统可用性进行了综合评价。主要结论如下。

第一，GazeNetV2 能够有效完成三维视线方向回归。在固定训练集、验证集和测试集划分下，模型在 1390 条测试样本上取得 2.8206° 的平均角度误差、1.98° 的中位角度误差和 314.5413 px 的平均屏幕像素误差。该结果表明，双眼共享卷积结构能够从左右眼图像中学习视线相关特征，模型具备作为系统深度学习主模型的基础能力。

第二，模型在跨用户条件下具有较好的泛化基础。31 名用户留一交叉验证结果显示，GazeNetV2 的 LOO 平均角度误差为 2.4788°，平均屏幕像素误差为 321.3820 px，其中 23 名用户的角度误差不超过 3°。该结果说明模型对多数新用户具有较好的适应能力，但仍存在少数长尾用户误差较大的现象。长尾误差主要与眼部外观差异、眼镜反光、摄像头角度、头部姿态范围和采集质量等因素有关。

第三，屏幕像素误差受几何映射和校准策略显著影响。固定测试集和跨用户实验均表明，角度误差较低并不必然对应较低屏幕像素误差。普通摄像头系统缺少精确相机标定，摄像头位置、屏幕距离、用户坐姿和头部运动都会影响三维视线到屏幕点的映射。因此，屏幕级注视交互不能只依赖模型输出，还需要几何映射、用户校准和平滑处理共同作用。

第四，用户校准能够有效修正系统性偏差。少点校准对比实验表明，9 点 affine 校准能够将平均像素误差从 314.5 px 降低到 221.2 px，说明少量校准点已经能够显著修正系统偏移。相比之下，9 点 polynomial 映射误差升高到 437.0 px，说明在校准点较少时，高阶映射容易受到噪声影响而产生过拟合。最终系统采用 25 点实时校准流程，以利用更完整的屏幕覆盖范围提高真实交互阶段的校准稳定性。

第五，头姿信息对视线估计和屏幕映射具有重要作用。头姿消融实验显示，引入头姿相关信息后，像素误差由 501.9 px 降低到 365.0 px，改善幅度约为 27.3%。该结果说明用户头部姿态变化会显著影响视线估计和屏幕映射。然而，普通摄像头条件下的 PnP 头姿估计也会受到关键点质量、相机内参近似和坐标约定影响。因此，头姿补偿必须与训练标签、模型输出和实时几何映射保持一致，否则可能引入新的系统误差。

第六，Classic 与 Deep 双模式具有互补意义。Classic 模式结构轻量、过程可解释，在大目标选择和停留触发场景中具有较好的连续性；Deep 模式体现了本文深度学习模型训练和三维视线估计的主要研究成果，能够通过固定测试集和跨用户实验进行定量评价。两种模式共同说明，普通摄像头视线追踪系统既需要可解释、可演示的传统视觉实现，也需要具备学习能力和泛化基础的深度模型路线。

第七，Look2Act 已完成可运行系统闭环。系统功能测试表明，软件能够完成程序启动、模式选择、摄像头预览、人脸检测、25 点校准、实时追踪、全屏验证、交互启动器和五子棋演示等流程。系统适合用于注视点可视化、大目标选择、停留触发和普通摄像头视线交互原型验证。

## 7.3 当前系统存在的不足

虽然 Look2Act 已经完成了从数据采集到注视交互的软件闭环，但受普通摄像头硬件条件、数据规模和系统实现阶段限制，当前系统仍存在以下不足。

第一，屏幕像素误差仍然较大。GazeNetV2 的角度误差已经达到较低水平，但屏幕像素误差仍在数百像素量级。这说明模型方向估计和屏幕点交互之间仍存在明显系统差距。误差主要来自摄像头与屏幕几何参数近似、用户眼睛相对相机位置不确定、屏幕距离估计不精确以及校准采样质量差异。

第二，长尾用户适应能力仍需提升。留一用户交叉验证中，多数用户表现较好，但仍有少数用户误差明显偏大。这类用户可能受到眼镜反光、眼睑遮挡、虹膜颜色、摄像头角度、采集质量和注视习惯等因素影响。当前模型尚未针对长尾用户进行个性化适配，也未建立专门的困难样本处理机制。

第三，实时头姿补偿仍有改进空间。系统已经实现 PnP 头姿估计，并在实验中证明头姿信息具有重要作用。但由于普通摄像头缺少精确内参，人脸关键点存在帧间抖动，三维人脸模型点也只是近似描述，实时头姿直接参与几何变换时可能带来额外误差。当前系统在 Deep 演示配置中采用更稳定的相机空间契约，尚未实现完全鲁棒的动态头动补偿。

第四，校准流程仍存在用户负担。最终系统采用 25 点校准，能够覆盖较完整屏幕区域，但相比少点校准，用户操作时间更长。少点校准虽然负担较低，但映射稳定性不足。如何在校准点数量、校准时间、拟合稳定性和交互精度之间取得更好平衡，仍需要进一步研究。

第五，交互任务仍以大目标和演示型任务为主。当前系统适合注视点可视化、大目标选择、停留触发和五子棋等原型演示，但尚不能稳定替代鼠标完成小目标精确点击。普通 RGB 摄像头视线追踪的精度、抖动和延迟限制了其在高精度桌面操作中的应用范围。

第六，系统级用户实验仍不够充分。本文已经完成模型评估、跨用户实验、校准对比和功能测试，但大规模用户交互实验仍有限。对于注视交互系统而言，用户主观负担、操作疲劳、误触发体验、学习成本和长时间稳定性同样重要，这些内容需要在后续工作中进一步验证。

## 7.4 后续工作展望

针对当前系统存在的不足，后续可从数据、模型、几何、校准、实时性和交互应用六个方向继续改进。

第一，扩充数据集并优化数据质量。后续可以继续采集更多用户、更多设备、更多光照条件和更多佩戴眼镜场景下的数据，增强模型对真实桌面环境的覆盖能力。同时，应加强数据质量控制，对高误差用户、高误差设备和异常样本进行专项分析，建立困难样本标记和补采机制。数据扩充不应仅追求样本数量，还应关注用户多样性、设备多样性、姿态范围和屏幕区域覆盖。

第二，引入轻量化个性化适配方法。当前模型采用统一参数面对所有用户，难以完全消除个体差异。后续可以研究少样本个性化方法，例如利用少量校准样本调整输出偏置、更新轻量映射层或训练用户特定校正模块[9,10]。在保证用户负担较低的前提下，个性化适配有望显著改善长尾用户表现。

第三，完善摄像头与屏幕几何标定。屏幕像素误差的重要来源是几何近似。后续可以引入更精确的摄像头内参估计、屏幕物理尺寸测量、摄像头相对屏幕位置估计和用户眼睛位置建模，使三维视线到屏幕平面的映射更加稳定。同时，可以研究将几何参数作为校准过程的一部分进行联合优化，而不是完全依赖固定经验参数。

第四，改进头姿建模和动态头动补偿。后续可以进一步统一训练标签、模型输出、PnP 姿态和实时几何映射之间的坐标约定，减少不同坐标空间之间转换带来的误差。在模型层面，可以探索将头姿信息作为辅助监督、门控特征或显式几何约束；也可以探索从完整摄像头帧直接预测视线信息的端到端方法[18]。在系统层面，可以提高头姿估计稳定性，并分析不同头姿范围下的误差分布。

第五，优化校准策略和交互稳定性。后续可以比较 5 点、9 点、13 点、25 点等不同校准点数量，结合 affine、多项式、局部加权回归或鲁棒回归方法，寻找校准负担和误差修正之间的更优折中。平滑方面，可以进一步比较指数滑动平均、Kalman 滤波、One Euro Filter 和基于速度的自适应平滑策略[15]，提高系统在快速视线转移和稳定注视两种状态下的表现。

第六，扩展注视交互任务和用户研究。当前 Look2Act 已实现注视光标、停留触发、交互启动器和五子棋演示。后续可以设计更系统的目标选择实验，记录成功率、完成时间、误触发次数、停留时间和用户主观评分，进一步评价系统在人机交互任务中的可用性。也可以探索无接触控制、辅助输入、阅读行为分析和多模态交互等应用方向，将视线输入与鼠标、键盘、语音或手势结合，提高交互可靠性。

第七，提升软件工程化和部署能力。后续可以进一步优化系统启动速度、模型加载速度、日志管理、异常提示和界面交互体验；同时减少打包体积，完善安装流程和用户配置管理。对于实时推理部分，可以继续优化 ONNX Runtime 推理、摄像头分辨率、关键点检测频率和界面绘制逻辑，以提高不同设备上的运行稳定性。

## 7.5 本章小结

本文完成了一套基于普通 RGB 摄像头的实时视线追踪与注视交互系统 Look2Act。系统以 Deep/GazeNetV2 作为深度学习研究主线，以 Classic 与 Deep 双模式作为软件实现主线，完成了数据采集、数据预处理、模型训练、三维视线估计、屏幕映射、用户校准、平滑处理、全屏验证和注视交互等核心工作。

```python
def process_frame(self, frame_bgr: np.ndarray) -> TrackerResult:
    timings = {}
    backend = self.config.normalized_backend

    face_result = self.face_detector.detect(frame_bgr)
    if not face_result.detected:
        fallback = self._last_valid_result
        if fallback is not None:
            return TrackerResult(gaze_point=fallback.gaze_point, valid=True, fps=self._calculate_fps(),
                                 timings=timings, error_message="未检测到人脸，使用上一帧结果",
                                 face_detected=False, backend=backend)
        return TrackerResult(gaze_point=None, valid=False, fps=self._calculate_fps(), timings=timings,
                             error_message="未检测到人脸", face_detected=False, backend=backend)

    if backend == "classic":
        return self._process_classic_result(face_result, timings)

    head_pose = self.head_pose_estimator.estimate(face_result.pnp_points_2d)
    if not head_pose.valid:
        return TrackerResult(gaze_point=None, valid=False, fps=self._calculate_fps(), timings=timings,
                             error_message="头部姿态估计失败", face_detected=True, backend=backend)

    left_eye, right_eye = face_result.left_eye_crop, face_result.right_eye_crop
    left_eye, right_eye = self._prepare_deep_eye_inputs(left_eye, right_eye)
    left_rgb = cv2.cvtColor(left_eye, cv2.COLOR_BGR2RGB)
    right_rgb = cv2.cvtColor(right_eye, cv2.COLOR_BGR2RGB)
    left_chw = np.ascontiguousarray(left_rgb.transpose(2, 0, 1), dtype=np.float32) / 255.0
    right_chw = np.ascontiguousarray(right_rgb.transpose(2, 0, 1), dtype=np.float32) / 255.0

    head_pose_vec = np.zeros(3, dtype=np.float32)
    inputs = {"left_eye": left_chw[None], "right_eye": right_chw[None], "head_pose": head_pose_vec[None]}
    gaze_vector = self.onnx_session.run([self.onnx_output_name], inputs)[0][0]

    d = gaze_vector.astype(np.float64)
    d = d / np.linalg.norm(d)
    ray_origin, ray_direction = self._compute_deep_ray(d, head_pose)
    intersection = self.screen_geometry.ray_plane_intersect(ray_origin, ray_direction)
    raw_point = self.screen_geometry.world_to_screen_px(intersection, clamp=not self._calibration_mode)
    smoothed_point = raw_point if self._calibration_mode else self.smoother.update(raw_point)
    result = TrackerResult(gaze_point=smoothed_point, valid=True, fps=self._calculate_fps(),
                           timings=timings, error_message=None, face_detected=True,
                           raw_point=raw_point, backend="deep")
    self._last_valid_result = result
    return result
```

```python
def detect_pupil_centroid(eye_roi: np.ndarray) -> Optional[tuple[float, float]]:
    if eye_roi is None or eye_roi.size == 0:
        return None

    gray = cv2.cvtColor(eye_roi, cv2.COLOR_BGR2GRAY)
    k = max(3, int(min(eye_roi.shape[:2]) / 8) | 1)
    gray = cv2.GaussianBlur(gray, (k, k), 0)
    try:
        _, thresh = cv2.threshold(gray, 0, 255, cv2.THRESH_BINARY_INV + cv2.THRESH_OTSU)
    except cv2.error:
        _, thresh = cv2.threshold(gray, 40, 255, cv2.THRESH_BINARY_INV)

    mk = max(3, int(min(eye_roi.shape[:2]) / 20) | 1)
    kernel = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (mk, mk))
    thresh = cv2.morphologyEx(thresh, cv2.MORPH_OPEN, kernel, iterations=1)
    thresh = cv2.morphologyEx(thresh, cv2.MORPH_CLOSE, kernel, iterations=1)

    contours, _ = cv2.findContours(thresh, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    if contours:
        contour = max(contours, key=cv2.contourArea)
        if cv2.contourArea(contour) >= 10:
            moments = cv2.moments(contour)
            if moments["m00"] != 0:
                return (moments["m10"] / moments["m00"], moments["m01"] / moments["m00"])

    inv = 255.0 - gray.astype(np.float32)
    yy, xx = np.indices(gray.shape)
    return (float(np.sum(xx * inv) / (np.sum(inv) + 1e-6)),
            float(np.sum(yy * inv) / (np.sum(inv) + 1e-6)))


def _process_classic_result(self, face_result, timings: dict[str, float]) -> TrackerResult:
    left_pupil = detect_pupil_centroid(face_result.left_eye_roi)
    right_pupil = detect_pupil_centroid(face_result.right_eye_roi)
    left_abs = absolute_pupil_point(left_pupil, face_result.left_eye_origin)
    right_abs = absolute_pupil_point(right_pupil, face_result.right_eye_origin)
    feature = fuse_eye_features(left_abs, right_abs, *face_result.frame_size, method="classic_pupil")
    raw_point = feature.point
    return TrackerResult(gaze_point=raw_point, valid=True, fps=self._calculate_fps(),
                         timings=timings, error_message=None, face_detected=True,
                         raw_point=raw_point, backend="classic")
```

### A.6 GazeNetV2 模型结构

**程序清单 A-6 双眼共享 CNN 与头姿融合模型**

文件路径：`src/models/gaze_net.py`

功能说明：该片段展示 GazeNetV2 的核心结构，包括左右眼共享卷积骨干、单眼 256 维特征提取、头姿融合、515 维融合特征、全连接回归和 L2 归一化输出。

```python
class GazeNetV2(nn.Module):
    def __init__(
        self,
        num_channels: list[int] | None = None,
        head_pose_dim: int = 3,
        fusion_dim: int = 128,
        dropout: float = 0.3,
    ):
        super().__init__()
        if num_channels is None:
            num_channels = [32, 64, 128, 256]

        self.eye_features = nn.Sequential(
            nn.Conv2d(3, num_channels[0], kernel_size=3, padding=1),
            nn.BatchNorm2d(num_channels[0]), nn.ReLU(inplace=True), nn.MaxPool2d(2),
            nn.Conv2d(num_channels[0], num_channels[1], kernel_size=3, padding=1),
            nn.BatchNorm2d(num_channels[1]), nn.ReLU(inplace=True), nn.MaxPool2d(2),
            nn.Conv2d(num_channels[1], num_channels[2], kernel_size=3, padding=1),
            nn.BatchNorm2d(num_channels[2]), nn.ReLU(inplace=True), nn.MaxPool2d(2),
            nn.Conv2d(num_channels[2], num_channels[3], kernel_size=3, padding=1),
            nn.BatchNorm2d(num_channels[3]), nn.ReLU(inplace=True), nn.MaxPool2d(2),
        )
        self.eye_pool = nn.AdaptiveAvgPool2d(1)
        feat_dim = num_channels[3] * 2 + head_pose_dim
        self.fusion = nn.Sequential(
            nn.Linear(feat_dim, fusion_dim),
            nn.ReLU(inplace=True),
            nn.Dropout(dropout),
            nn.Linear(fusion_dim, 3),
        )

    def _extract_eye_features(self, eye_img: torch.Tensor) -> torch.Tensor:
        x = self.eye_features(eye_img)
        x = self.eye_pool(x)
        return x.view(x.size(0), -1)

    def forward(self, left_eye: torch.Tensor, right_eye: torch.Tensor, head_pose: torch.Tensor) -> torch.Tensor:
        left_feat = self._extract_eye_features(left_eye)
        right_feat = self._extract_eye_features(right_eye)
        fused = torch.cat([left_feat, right_feat, head_pose], dim=1)
        out = self.fusion(fused)
        return F.normalize(out, p=2, dim=1)
```

```python
def ray_plane_intersect(self, ray_origin: np.ndarray, ray_direction: np.ndarray) -> Optional[np.ndarray]:
    if self._plane_normal is None or self._plane_origin is None:
        return None
    return ray_plane_intersect(
        ray_origin,
        ray_direction,
        self._plane_origin,
        self._plane_normal,

def world_to_screen_px(self, point_3d: np.ndarray, clamp: bool = True) -> tuple[float, float]:
    if self._plane_origin is None:
        return 0.0, 0.0

    p = np.asarray(point_3d, dtype=np.float64).flatten()
    delta = p - self._plane_origin
    local_x_mm = np.dot(delta, self._screen_x_axis)
    local_y_mm = np.dot(delta, self._screen_y_axis)
    px = local_x_mm / self.screen_w_mm * self.screen_w_px
    py = local_y_mm / self.screen_h_mm * self.screen_h_px
    if clamp:
        px = float(np.clip(px, 0, self.screen_w_px - 1))
        py = float(np.clip(py, 0, self.screen_h_px - 1))
    return float(px), float(py)
```

功能说明：该片段展示校准模块如何将原始注视点映射为校准后的屏幕坐标，并使用指数滑动平均降低实时输出抖动。

```python
def apply(self, raw_gaze: tuple[float, float]) -> tuple[float, float]:
    if not self._calibrated or self._transform_matrix is None:
        return raw_gaze
    normed_x = (raw_gaze[0] - self._norm_mean[0]) / self._norm_std[0]
    normed_y = (raw_gaze[1] - self._norm_mean[1]) / self._norm_std[1]
    feat = np.array(self._build_feature_row(normed_x, normed_y), dtype=np.float64)
    result = self._transform_matrix @ feat
    return (float(result[0]), float(result[1]))


def _apply_calibration_and_clamp_with_debug(self, gaze_x: float, gaze_y: float):
    if self.calibrator is not None and self.calibrator.is_calibrated:
        gaze_x, gaze_y = self.calibrator.apply((gaze_x, gaze_y))
    pre_clamp = (gaze_x, gaze_y)
    screen = QApplication.primaryScreen()
    if screen is not None:
        geo = screen.geometry()
        gaze_x = max(0.0, min(gaze_x, float(geo.width() - 1)))
        gaze_y = max(0.0, min(gaze_y, float(geo.height() - 1)))
    return (gaze_x, gaze_y), pre_clamp


class GazeSmoother:
    def __init__(self, alpha: float = 0.3):
        assert 0.0 < alpha <= 1.0
        self.alpha = alpha
        self._prev: Optional[tuple[float, float]] = None

    def update(self, point: tuple[float, float]) -> tuple[float, float]:
        if self._prev is None:
            self._prev = point
            return point
        sx = self.alpha * point[0] + (1.0 - self.alpha) * self._prev[0]
        sy = self.alpha * point[1] + (1.0 - self.alpha) * self._prev[1]
        self._prev = (sx, sy)
        return (sx, sy)
```

### B.7 常见问题与处理方式

| 问题 | 处理建议 |
| --- | --- |
| 摄像头打不开 | 检查摄像头是否被其他程序占用，并在系统权限中允许应用访问摄像头。 |
| 检测不到人脸 | 调整坐姿、摄像头角度和光照，使完整面部位于画面中央。 |
| 眼镜反光明显 | 降低屏幕亮度或调整环境光方向，避免镜片上出现强反光区域。 |
| 校准效果差 | 重新进入摄像头预览确认检测稳定后，再按目标点顺序重新校准。 |
| Deep 模式注视点偏移 | 重新完成校准，并检查模式配置与所加载模型资源是否一致。 |
| 光标抖动 | 保持头部和坐姿稳定，必要时提高平滑强度或重新校准。 |
