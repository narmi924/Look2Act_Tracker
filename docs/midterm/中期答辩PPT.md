# 中期答辩PPT每页描述

这份中期答辩 PPT 不建议按“做了什么”平铺直叙，而应当围绕一条更清晰的主线展开：

开题阶段回答的是“为什么做、准备怎么做”；  
中期阶段要回答的是“原来提出的技术路线是否已经被验证、关键风险是否已经收敛、后半程该如何把系统做完整并形成论文结论”。

建议整套 PPT 控制在 **14-15 页左右**，逻辑上分为四段：
1. 开题回顾与中期问题定义
2. 已完成工作的核心成果
3. 当前发现的问题与原因分析
4. 后续计划与最终预期成果

需要专业绘制/生图的示意图统一编号如下：
- `图G-01`：普通 RGB 摄像头桌面视线追踪应用场景示意图
- `图G-02`：开题目标到中期验证逻辑总览图
- `图G-03`：自建数据采集与数据处理流程图
- `图G-04`：GazeNetV2 模型结构与信息融合示意图
- `图G-05`：实时视线追踪系统端到端流程架构图
- `图G-06`：后续工作路线图（从“证明可行”到“证明可用”）

## 第7页 已完成工作二：模型从基线到 GazeNetV2

**标题建议**：模型不是一次成型，而是沿着问题逐步迭代

**页面内容描述**：
- 先简单交代初期基线：单眼输入模型，能够跑通训练与推理链路，但泛化能力有限。
- 再说明当前改进模型 GazeNetV2：
  - 双眼共享 CNN 特征提取
  - 融合 head pose 信息
  - 输出三维视线方向向量
- 简要说明这样设计的原因：
  - 双眼信息比单眼更稳定
  - 头部姿态不仅影响后处理映射，也应进入模型特征空间
  - 三维视线回归更符合后续几何映射需求

**讲述重点**：
- 这一页不要陷入网络层数细节，而是要讲“为什么这样改”。

## 第10页 阶段性结果三：系统链路中的关键因素已经被量化

**标题建议**：不仅有结果，还知道结果为什么会这样

  - 误差下降约 **27.3%**
- 展示校准策略对比结果：
  - 无校准：**314.5 px**
  - 9 点 affine：**221.2 px**
  - 9 点 polynomial：稳定性较差，存在过拟合
- 得出阶段性判断：
  - head pose 是当前系统中必要的精度提升因素

**讲述重点**：

## 使用建议

1. 不要把中期答辩做成“中期报告文字搬运”。
   中期 PPT 更强调逻辑推进和结论表达，文字应更少，图表应更多。

2. 对实验结果的表述要区分“已经验证”与“还需完善”。
   比如跨用户泛化、head pose 贡献、9 点 affine 稳定性，这些可以作为阶段性结论明确说；
   而系统级真实交互效果、长尾用户补偿、最终论文结论，则应说成后续工作重点。

3. 每一页尽量只表达一个中心结论。
   例如“数据链路已建成”“跨用户结果已验证”“剩余瓶颈集中在映射和长尾用户”，不要一页塞太多意思。

4. 中期答辩最好的状态不是“看起来已经全部做完”，而是“主体已经完成、证据已经充分、剩余工作边界清楚”。

5. 对需要生图的页面，只生成概念图、结构图、流程图和场景示意图；真实实验结果图必须使用仓库中的真实图片，不要让生图模型替代实验图。
